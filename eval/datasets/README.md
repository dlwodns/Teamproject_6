- 테스트셋 오답을 보고 규칙을 고치면 그 테스트셋은 개발 세트가 된다. 그때는 데이터 버전을 올려 dev로 옮기고 새 테스트 메일을 만든다.

### test-v1 작성 방식

- 개발 세트와 같은 가상 메일함(클라우드전환1팀 이준호 팀장), 수신일 2026-10-26(월). 외부 인물 1명(대한카드 오지훈 과장) 추가.
- 규칙 파일(`ai/app/pipeline/rules`)을 열기 전에 메일과 정답을 먼저 썼다. 라벨 관례(유형 · 마감 해석 · 공지 속 지목)는 `data/dummy/README.md` 5절과 개발 세트를 따랐다.
- 개발 세트에 없던 표현 · 상황: EOD · ASAP · 금일 중 · 모레 · 차주 · 가부 · "편하실 때" · "~해야 합니다"(암시 요청) · 역할 지목("각 팀장은") · 조건부 회신("이상 없으면 생략") · 자동회신 · 일정 취소 · 나를 CC에 둔 타인 대상 요청 · TO로 받은 단순 공유.
- 정의: `data/dummy/mails_test.py` → `cd data/dummy && python build.py test` (검증 오류 0).

### 한계

- **정답 라벨은 사람이 붙이지 않았다.** Claude가 쓰고 라벨을 붙였다. `data/dummy/test_mail_list.md`로 사람 검수가 필요하다(D15). 특히 애매하게 판단한 건: M-0006(이상 없으면 회신 생략 → Task로 봄), M-0009 · M-0026 · M-0037(조건부 회신 → Task 아님), M-0036(마감 없는 암시 요청 → Task).
- 규칙 작성자(Claude)와 같은 작성자라 완전히 독립적이지는 않다. 규칙은 보지 않았지만 개발 세트는 봤다.
