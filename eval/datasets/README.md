### test-v1 작성 방식

- 개발 세트와 같은 가상 메일함(클라우드전환1팀 이준호 팀장), 수신일 2026-10-26(월). 외부 인물 1명(대한카드 오지훈 과장) 추가.
- 규칙 파일(`ai/app/pipeline/rules`)을 열기 전에 메일과 정답을 먼저 썼다. 라벨 관례(유형 · 마감 해석 · 공지 속 지목)는 `data/dummy/README.md` 5절과 개발 세트를 따랐다.
- 개발 세트에 없던 표현 · 상황: EOD · ASAP · 금일 중 · 모레 · 차주 · 가부 · "편하실 때" · "~해야 합니다"(암시 요청) · 역할 지목("각 팀장은") · 조건부 회신("이상 없으면 생략") · 자동회신 · 일정 취소 · 나를 CC에 둔 타인 대상 요청 · TO로 받은 단순 공유.
- 정의: `data/dummy/mails_test.py` → `cd data/dummy && python build.py test` (검증 오류 0).

### 한계

- **정답 라벨은 사람이 붙이지 않았다.** Claude가 쓰고 라벨을 붙였다. `data/dummy/test_mail_list.md`로 사람 검수가 필요하다(D15). 특히 애매하게 판단한 건: M-0006(이상 없으면 회신 생략 → Task로 봄), M-0009 · M-0026 · M-0037(조건부 회신 → Task 아님), M-0036(마감 없는 암시 요청 → Task).
- 규칙 작성자(Claude)와 같은 작성자라 완전히 독립적이지는 않다. 규칙은 보지 않았지만 개발 세트는 봤다.

## 3. v4 명령 시험 세트 (`agent_commands_v4.jsonl`, 2026-11-03)

명령 해석(`/agent/plan`) 독립 시험용 100문장. v1은 규칙 작성자가 함께 만들어 만점이 의미가 없어 따로 만들었다.

| 세트 | 문장 | 쓰임 | 규칙 수정에 쓰기 |
|---|---|---|---|
| v1 | 26 | 규칙 작성자가 함께 만든 회귀 확인용 | O |
| v2 | 120 (정상 60 · 반례 20 · 애매 20 · 지원 외 20) | 개발 세트. 11/3 `agent_rules_v1.4`는 이 세트 오답만 보고 고쳤다 | O |

| v3 | 120 (v2와 같은 구성) | 봉인 시험 세트. 버전마다 한 번 재고 문장 · 오답은 보지 않는다 | **X** |

| 범위 밖 · 지원 외 | 16 | 메일 · 일정 관련이지만 14개 행동에 없는 것(삭제 · 전달 · 외부 주소 새 메일 · 캘린더 등록 · 회의 · 번역 · 자동응답 · 서명 · 첨부 · 공유 · 백업 · 차단 · 예약 발송 등) |

- 줄 형식: `id · now · text · selected_mail_ids · last_result_ids · expected · type(정상 | 범위 밖) · sub(행동 ID | 지원 외 | 무관 | 지시 아님)`. 이 칸이 있으면 `run_agent_commands.py`가 행동별 표 · 거르기 표 · 위험한 오탐 목록 · 경로별 건수를 더 낸다.
- 범위 밖 30문장 중 21문장은 행동 단어(완료 · 처리 · 재촉 · 미뤄 · 빼 · 알림 · 초안 · 요약 · 보내)를 넣은 함정이다.
- expected에는 문장에 드러난 target · params 칸만 적었다. 문서에 없는 관례('다음 주' · '이번 달' 범위, T09 `rule` 값, 기한 전 알림 인자 이름, 템플릿 이름, `tone` · `topic` 값)는 넣지 않았다. '이번 주'는 v1 라벨처럼 월~일, 시각 없는 T05 날짜는 08:30(AI detail 4.4절)이다.
- `now`는 11-02(월) 외에 11-04(수) · 11-05(목) · 11-06(금)을 섞어 상대 날짜 계산을 시험한다.

### 작성 방식 · 독립성 범위

- 출제자는 규칙 · 프롬프트와 분리했다. `ai/app/agent/` · `ai/app/prompts/agent_v1.py` · 예시 세트 · v2 · v3 · 기존 명령 채점 보고서를 열지 않고 AI detail 2 · 3 · 4.4 · 7절과 `ai/app/schemas/agent.py`만 보고 썼다.
- 겹침 검사는 스크립트로 기존 세트(v1 · v2 · v3 · 예시)의 `text`를 집합 비교만 했다: 완전 · 정규화(공백 · 문장부호 제거) 겹침 0, 유사도 0.8 이상 0(처음 5문장이 걸려 다시 썼다), 세트 안 중복 0.
- AI detail 2절 예시 명령을 살짝 바꾼 문장은 행동마다 1개 이하다.

### 한계

- **출제자도 Claude라 완전히 독립적이지 않다.** 규칙 파일은 보지 않았지만 같은 모델이 쓴 규칙과 같은 말버릇을 공유할 수 있다. 사람 검수가 필요하다.
- 라벨이 갈릴 수 있는 문장: V-073(외부 주소로 새 메일 '보내 줘' → T12 초안으로 볼 여지), V-081 · V-084(지원하는 행동이 일부 섞인 요청), V-086(알림 '소리' → T09로 볼 여지), V-049(발신자 단위 제외를 T10으로 봄), 지시 아님 8문장의 reason(부정 · 기능 질문 · 감정 = unsupported, 과거 서술 = ambiguous).
