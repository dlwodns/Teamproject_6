# EXAONE 로컬 모델 메일 분류 테스트 (2026-10-24)

## 조건
- 노트북: LG gram, RAM 16GB, CPU만 사용
- 모델: EXAONE 4.0 1.2B (Q8_0), EXAONE 3.5 7.8B (Q4_K_M), Ollama 0.34.0
- 테스트 메일: 가상 업무 메일 8통 (mails.json, 정답 포함)
- A: 기존 프롬프트 / B: 규칙 프롬프트 + JSON 스키마 강제 / C: B 결과에 코드 후처리 규칙 적용

## 공통으로 놓친 부분 → 규칙
| 놓친 부분 | 프롬프트 규칙 (B) | 코드 후처리 규칙 (C) |
|---|---|---|
| 연도를 2023으로 씀 | 오늘 날짜(2026-10-24) 명시, 연도 없으면 2026 | 메일에 연도가 없으면 올해로 교정 |
| 상대 날짜(오늘·내일) 처리 | 오늘 기준 환산 | - |
| 시간 없는 마감 처리 제각각 | 시간 없으면 18:00 | 날짜만 있으면 18:00 추가 |
| 공지·참고 메일에도 할 일 생성 | 공지·뉴스레터·참고용은 false, action "없음" | false면 마감·할 일 비움 |
| 우선순위 기준 불명확 | 긴급 또는 3일 이내 high, 나머지 medium, 할 일 없으면 low | 같은 기준으로 재계산 |
| 요약 20자 초과 | 20자 이내 | 20자로 자름 |
| JSON이 아닌 답 | 예시 1개 + JSON 스키마 강제 | - |

- 후처리(C)는 코드만 돌리므로 추가 시간이 없다.

## 결정
- 7.8B + 규칙 프롬프트 + 후처리를 로컬 분류기 후보로 정한다. 근거: 8통 모두 정답, 메일 1통 약 25초.
- 1.2B는 분류기에서 제외한다. 근거: 할 일이 없는 공지 메일 4통을 모두 "할 일 있음"으로 판단했고, 마감일을 지어냈다. 형식 문제가 아니라 판단 능력 문제라 규칙으로 고치기 어렵다.
- 우선순위·연도·요약 길이는 모델에 맡기지 않고 코드로 처리한다. 근거: 규칙을 프롬프트에 넣어도 7.8B가 우선순위를 2통 틀렸고, 코드는 항상 같은 결과를 낸다.

## 한계
- 메일 8통, 작성자가 만든 가상 메일이다. 실제 메일(긴 스레드, 첨부, 영어 혼용)에서는 결과가 달라질 수 있다.
- 요약 20자 자르기는 문장이 중간에 끊긴다(예: "결재 요청 (마감: 1"). 실제 적용 시 다시 요약하게 하거나 길이 제한을 늘려야 한다.
- 채점 기준(18:00 기본값, 3일 이내 high)은 작성자가 정한 규칙이다.
