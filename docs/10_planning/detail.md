## 1. 한 줄 정의와 IR 포지셔닝

### 1.1 한 줄 정의

여러 메일 계정의 미처리 업무를 모아 보여 주고, 사용자가 말로 지시하면 에이전트가 처리하며, **처리 완료 체크까지 추적하고 리마인드하는 웹 앱**

### 1.2 IR 포지셔닝 `[확정]`

> **"그룹웨어를 바꾸지 않고, 쓰던 메일 위에서, 처리 완료까지. 모든 것은 사내 모델로, 외부 유출 없이."**

| 메시지 | 근거 | 시연에서 보여 줄 장면 |
|---|---|---|
| 그룹웨어를 바꾸지 않음 | 두레이 · 네이버웍스 AI는 자기 메일함 안에서만 동작한다. 우리는 쓰던 Outlook 계정을 그대로 연결한다(메일 앱은 바꾸지 않는다) | Outlook 테스트 계정 그대로 연결 |
| 쓰던 메일 위에서 | 여러 계정의 미처리 메일을 한곳에 모은다 | 계정 2개 동시 표시 |
| 처리 완료까지 | 우리는 완료 체크까지 추적 · 리마인드한다. 답장을 보낸 뒤에도 완료를 확인한다(D48) | 리마인더 도착 → 처리 → 추적 종료 |
| 사내 모델, 외부 유출 없음 | 서비스 경로는 엑사원 자체 운영. 외부 LLM API 호출 0건 (D41). 백엔드는 AI에 개인정보를 가린 메일만 넘긴다 | 외부 송신 로그 0건 화면 `[제안]` |

- 발표 범위 `[확정: 문규남 11-03]`: "AI 처리 과정에서 외부로 나가지 않는다"로 한정한다. 시연은 Outlook 테스트 계정을 연결하므로(백엔드는 Outlook(Graph)만, PR #5 리뷰 11-03) 메일 자체는 원래 외부 메일 서비스에 있다. "메일이 외부로 전혀 안 나간다"고 말하지 않는다.
- 경쟁 비교 `[확정: PR #5 리뷰 11-04]`: "경쟁 서비스는 요약 · 우선순위에서 끝난다"고 말하지 않는다. 후속 리마인드는 Superhuman · Shortwave · Gmail에도 있다(`refs/benchmark.md`). 우리 강점은 메일마다 따로 걸지 않아도 업무를 뽑고, 완료 체크까지 추적하는 것이다.
- 연동 표현 `[확정: PR #5 리뷰 11-04]`: 지금 연결하는 것은 Outlook 테스트 계정과 별도 웹 앱이다. 사내 Outlook · 그룹웨어 연동은 하지 않았으므로 도입 구상(13.1절)으로 구분해 말한다.
- 음성 `[결정 필요]`: 브라우저 음성인식(Web Speech API, D29 1차)은 음성이 브라우저 제조사 서버로 간다. 이 방식으로 시연하면 "AI 처리 과정에서 외부로 나가지 않는다"에서 음성은 예외라고 밝히거나, 서버 음성인식(Whisper)으로 시연한다.
- 모델 표현 `[확정: 문규남 11-03]`: 우리가 돌리는 것은 공개 모델 EXAONE 3.5 7.8B다. 챗엑사원은 같은 엑사원 계열로 만든 별도 서비스이므로 "챗엑사원을 돌린다"고 하지 않고 "챗엑사원과 같은 엑사원 계열 모델"이라고 한다. LG 사내 이관 방향은 13.1절.

### 1.3 기능 위계 `[확정]` (D42)

- 기본 기능: 요약, 초안. 있어야 하지만 차별점이 아니다. 시연은 짧게 한다.
- 시연 중심: **행동형 에이전트**. 말하면 상태가 바뀌고, 끝날 때까지 추적된다.

### 1.4 서비스 이름 · 주제 `[제안]`

**주제가 넓어진 흐름**

| 단계 | 이름 | 사용자가 얻는 것 |
|---|---|---|
| 과제 원안 (10/03) | 미처리 메일 리마인더 봇 | 답하지 않은 메일을 다시 알려 줌 |
| 확장 1 (10/24~10/31) | 업무 누락 방지 대시보드 | 메일 속 업무를 뽑아 한 화면에서 급한 것부터 지워 나감 (D13 · D20) |
| 확장 2 (11/02) | 메일 업무 누락 방지 AI 비서 | 말로 시키면 처리하고, 완료 체크까지 추적 · 리마인드 (D35 · D37 · D43) |

리마인더(알림) → 대시보드(보기) → 비서(대신 처리 + 끝까지 챙김)로 역할이 넓어졌다. 이제 '봇'이나 '대시보드'로는 시연 중심인 행동형 에이전트와 처리 완료 추적을 담지 못한다.

**주제명 제안: 「메일 업무 누락 방지 AI 비서」**

- 처음 안은 '업무관리 비서'였다. '업무관리'는 Jira · To Do · 플래너 같은 업무관리 도구 전반으로 읽혀 범위가 넓어 보이고, 1순위 목표(누락 0건, D13)와 '메일에서 출발한다'(인터뷰: 업무 회신은 메일로만)가 드러나지 않는다.
- '메일 업무'로 입력 범위를, '누락 방지'로 1순위 목표를, 'AI 비서'로 행동형 에이전트를 함께 보여 준다.
- 한 줄 슬로건 후보: **"놓친 업무는 찾아 주고, 끝날 때까지 챙겨 주는 메일 업무 비서"** (IR 포지셔닝 1.2와 함께 쓴다).

**서비스 이름 제안: CNE (씨애니 · seeany)**

| 풀이 | 뜻 |
|---|---|
| 발음 · 애칭 | 씨애니 = **see any** — 메일 속 업무를 하나도 놓치지 않고 본다 |
| 머리글자 | **C**atch · **N**udge · **E**nd — 놓친 업무를 잡고(추출 · 대시보드), 슬쩍 다시 알리고(리마인더), 끝까지 마무리한다(완료 체크까지 추적). 핵심 기능 세 개와 1:1로 맞는다 |
| 대상 | LG CNS의 'CNS'에서 한 글자만 바꿔, LG CNS 팀장을 위한 서비스라는 점과 사내 엑사원 · 에이전틱웍스 연동(보완 포지셔닝, 13절)을 떠올리게 한다 |

비교한 다른 후보:

| 후보 | 장점 | 고르지 않은 이유 |
|---|---|---|
| 업무관리 비서 | 쉽다 | 위와 같이 범위가 넓고 차별점(누락 방지 · 완료 추적)이 안 보인다 |
| Closer (끝까지 닫는 비서) | '처리 완료까지'와 바로 연결 | 영업 용어로 굳어 있고, LG CNS 맥락이 없다 |
| 놓침제로 | 목표(누락 0건)가 그대로 보인다 | 기능 이름에 가깝고 서비스 이름으로는 약하다 |

## 4. 처리 완료 추적 · 리마인더

### 4.1 상태 머신 `[확정]` (D36 · 구조도 v3.1 5절)

```
미처리 ──완료──▶ 완료 ──되돌리기──▶ 미처리
미처리 ──제외──▶ 제외 ──되돌리기──▶ 미처리
미처리 ──나중에(until)──▶ 나중에 ──until 도래──▶ 미처리 (리마인더 발송)
```

- 상태는 업무(`tasks`) 단위로 둔다. 한 메일에 업무가 여러 개일 수 있기 때문이다(D20-6). 코드 값은 `pending` · `done` · `excluded` · `snoozed`.
- 추적 종료 조건은 사용자의 **완료 체크** 또는 **제외**뿐이다. 답장 뒤에는 완료 확인 팝업으로 묻는다 `[확정]` (D23 · D48, 4.4절). '오늘 하루 보지 않기'를 고른 날만 팝업 없이 바로 완료한다.
- 모든 전이는 `action_log`에 기록한다(누가 · 언제 · 어디서: UI / 에이전트 규칙 / 에이전트 모델 / MCP).

### 4.2 리마인더 규칙 `[결정: 문규남 11-02 · 팀 리뷰 대기]` (기본값은 설정에서 바꾼다)

| 규칙 | 조건 | 기본값 |
|---|---|---|
| R-아침 | 미처리 전체 (기한 없는 업무 포함) | **매일 1회, 사용자가 고른 시각. 기본 08:30** |
| R-기한 | 기한이 있는 미처리 | **기한 3시간 전** |
| R-나중에 | 나중에 처리 시각 도래 | 해당 시각 |

- 이유: 08:30은 출근해 업무를 준비하는 시각이라 하루 할 일을 한 번에 보기 좋다. 기한 3시간 전에 알려야 미리 알고 대비할 수 있다.
- R-아침이 기존 R-요약(매일 1회 개수 요약)과 R-경과(기한 없는 미처리 N일마다)를 대신한다. 기한 없는 업무는 아침 알림 목록에 들어가므로 따로 간격 N을 두지 않는다.
- 업무가 생긴 시점에 이미 기한 3시간 안이면 R-기한을 바로 1회 보낸다 `[제안]`. 시간 없는 기한은 18:00으로 보정되므로(AI-T2) R-기한은 15:00에 간다.

- 발송 직전 재확인: 아직 미처리인지 다시 조회한 뒤 보낸다. 완료 · 제외면 건너뛰고 사유를 남긴다.
- 중복 방지: `reminders`의 `(task_id, rule, slot)` 유일 제약. `slot`은 규칙별 발송 시각(예: `2026-11-06T09:00`).
- 조용한 시간: 설정 시간대에는 보류했다가 다음 허용 시각에 보낸다.
- 스케줄러는 **단일 프로세스**로 운영하고, 시작할 때 DB에서 예약을 다시 만든다 (R3).
- 데모용 시간 이동 · 리마인더 강제 실행 엔드포인트는 개발 모드(`APP_MODE=dev`)에서만 켠다.

### 4.3 알림 채널 `[결정: 문규남 11-02 · 팀 리뷰 대기]`

목표: 일반 메신저 알림처럼 사용자가 앱을 보고 있지 않아도 알림이 눈에 띈다.

| 기기 | 보이는 방식 | 구현 |
|---|---|---|
| 노트북 · PC (앱을 열어 둠) | 카카오톡 알림처럼 화면 오른쪽 아래에 알림 창이 떴다가 사라짐 | 앱 내 토스트 + 알림 센터 기록 |
| 노트북 · PC (앱 탭이 뒤에 있거나 닫힘) | 운영체제 알림(Windows 알림 센터 · macOS 알림) | 웹 푸시 + Notification API |
| 휴대폰 | 다른 앱 알림처럼 잠금 화면 · 알림 창에 표시 | 웹 푸시(PWA 설치) |

- 모든 알림은 알림 센터에도 남겨 놓친 알림을 다시 볼 수 있게 한다.
- 웹 푸시는 HTTPS가 필요하다 → 11/14 배포 URL과 함께 확보.
- iOS 웹 푸시는 홈 화면에 설치했을 때만 동작한다 → 설정 화면에 설치 안내 (R4).
- Apprise는 다른 채널(메일 · 메신저) 확장용으로 유지한다.

### 4.4 답장 후 완료 확인 `[결정: 문규남 · 이재운 11-04]` (D48)

| 경로 | 언제 | 보여 주는 것 |
|---|---|---|
| (가) 기본 | 서비스 안에서 답장을 보낸 직후 | 같은 메일의 미완료 업무 + "완료할까요? 예 / 아니오" + '오늘 하루 보지 않기' |
| (나) 보조 | Outlook에서 보낸 답장을 보낸편지함 동기화로 감지했을 때 | 알림 센터에 "답장 보낸 업무가 있어요, 완료할까요?" |

- (가)로 이미 물은 업무는 (나)에서 다시 묻지 않는다.
- 닫거나 아무것도 고르지 않으면 리마인드를 유지한다(D23, 누락 0).
- '오늘 하루 보지 않기'를 고르면 그날 답장한 업무는 팝업 없이 바로 완료한다. 다음 날 R-아침 알림에 "어제 답장으로 완료된 업무 N건"과 되돌리기를 보여 준다(안전장치).
- 서비스 안 발송은 사용자가 보내기를 누를 때만 한다. 자동 발송은 없다. Graph `Mail.Send` 권한이 없으면 발송 기능을 숨긴다(R6).
- 모든 완료는 `action_log`에 남긴다. 바로 완료는 출처를 구분해 되돌리기 목록을 만들 수 있게 한다.

## 5. 응답 없는 메일 확인 · 재촉 `[결정: 문규남 11-02, 대상 범위 11-04 수정 · 팀 리뷰 대기]`

- 대상: 보낸편지함에서 수집한 내 발신 메일(`mails.direction = sent`).
- 판정: 같은 대화(`conversation_id`)에 상대 회신이 **기준일(기본 3일)** 동안 없으면 '응답 대기' 목록에 표시한다.
- 기준: 3일 이상 회신이 없으면 **무응답 메일만 모아** '응답 대기' 목록으로 보여 준다. 1단계 대상은 **내가 보낸 메일 중 요청한 메일만**이다(회신 요청 · 자료 제출 · 검토 · 참석처럼 상대의 답이 필요한 메일). 공지 · 공유 · 내가 보낸 답장 같은 메일은 넣지 않는다 `[결정: 문규남 11-04]`. 11-02 결정(전체 발신 메일, 자동 발송 제외)은 공지 · 기타 메일까지 잡혀 바꿨다.
- 요청 판정 `[결정 필요]`: 보낸 메일이 요청인지 무엇으로 판정할지(규칙 / 엑사원, AI-17 회신 필요 여부 판별은 지금 P2) AI · 백엔드가 정한다. 11/7 시연은 더미 정답(gold)으로 판정한다. 시드(#10) 기준으로는 보낸 메일 중 `category`가 요청 · 회신 · 검토인 메일을 센다. 여기서 `category` '회신'은 '회신 요청' 유형이고, 내가 보낸 답장('회신' 유형)은 `category` '기타'로 들어가 세지 않는다.
- 화면: '응답 대기' 목록 + 경과일. 자동 후속 발송은 없다.
- 재촉: 사용자가 원하면 에이전트에게 말해 **템플릿 기반 재촉 메일**을 보낸다(예: "답장 안 온 거 재촉 메일 보내줘"). 재촉은 템플릿 전송(T14)의 한 종류이며 항상 미리보기 → 확인 뒤에만 발송한다(D37 발송 유형). 상세는 7절.
- 구현 전제: 동기화가 보낸편지함도 가져오고, 사전 필터는 보낸 메일을 저장한 뒤 분류에서만 뺀다(구조도 v3.1 4절). 요청 판정을 엑사원으로 하면 이 전제가 바뀐다.

## 7. 템플릿 전송 · 재촉 (재촉 P1, 일반 템플릿 전송 P2)

- 포함 결정 `[결정: 문규남 11-02]`: 무응답 메일 재촉을 위해 템플릿 전송을 넣는다. 재촉 템플릿(종류 `nudge`)을 먼저 만들고, 그 밖의 템플릿 전송은 P2로 둔다.
- 재촉 기본 템플릿 예: "{수신자명}님, {보낸날짜}에 보내드린 '{원메일제목}' 건 확인 부탁드립니다."
- PRD · README 문구는 "자동 발송 없음, 사용자가 확인한 답장 · 템플릿 발송만"으로 고쳤다(11-04, D48).

- 흐름: 메일 선택 → 템플릿 선택 → 수신자 · 제목 · 본문 미리보기 → **확인** → 발송 → 결과 표시.
- 템플릿: 이름, 제목, 본문(자리표시자 `{수신자명}` · `{원메일제목}` 등), 소유자. 기존 `templates` 테이블에 종류 `send`와 제목 칸을 더한다(구조도 v3.1 9절).
- 기본 템플릿 예: "확인했습니다", "검토 후 회신드리겠습니다", "일정 조율 부탁드립니다".
- 발송 후에도 해당 업무는 **자동 완료하지 않는다**. 완료 체크는 사용자가 한다 (D36).
- 필요 권한: 메일 발송 권한 추가 동의 (Graph `Mail.Send` `[미확인: 테스트 계정 정책]`). 권한이 없으면 기능을 숨긴다 (R6).
- PRD '메일 앱 자체 기능 만들지 않음'과의 충돌은 11-04에 정리했다(D48: 자동 발송 없음, 사용자가 확인한 발송만).

## 13. 벤치마킹 결론 (조사일 2026-11-02)

조사 내용(해외 · 국내 · LG 사내 도구)과 출처는 `refs/benchmark.md` 맨 위 스크랩 「행동형 에이전트 · 국내 그룹웨어 · LG 사내 도구 묶음 조사 (2026-11-02)」에 있다. 여기에는 결론만 둔다.

1. 요약 · 초안 · 일정은 국내외 모두 기본 기능 → 차별점이 아니다.
2. 업계 흐름은 2026년 상반기 '요약 · 초안' → '행동형 에이전트'로 이동했다. 가장 가까운 경쟁은 NHN 두레이 '마이 에이전트'다.
3. 우리 차별점: **처리 완료까지 추적 + 리마인드, 기존 메일 위에서, 사내 모델로**.
4. LG CNS 대상으로는 a:xink와 경쟁이 아니라 **보완**으로 포지셔닝한다 `[제안]` — "a:xink가 아침에 알려 준 일이 실제로 끝났는지, 완료 체크까지 추적하고 다시 알림".
5. LG CNS 에이전틱웍스가 MCP 방식으로 연동하므로 행동을 MCP로 노출하는 구조를 둔다 (D43, AI detail 5절).
6. 참고 확인: a:xink가 메일 분류 · 미처리 추적 · 리마인드를 하는지 `[미확인]` → `refs/interview.md` 2차 질문지 '사내 도구 1'. 결과와 관계없이 우리 구현 계획은 바뀌지 않는다(13.1절). 공개 자료로는 "회의 · 이메일 · 번역을 에이전틱 AI로 전환하는 업무혁신 기능 7종 통합 서비스"까지만 확인된다(11-03 조사).
7. 세 도구 모두 내려받거나 외부에서 붙일 수 없다(11-03 조사). a:xink는 LG CNS가 기업에 구축하는 서비스(LG디스플레이 등 적용), 에이전틱웍스는 기업에 모듈 단위로 파는 플랫폼(금융 고객 중심 PoC), 챗엑사원은 임직원 대상 웹 서비스(기업 · 기관 메일 인증 공개 베타 보도). 내려받을 수 있는 것은 엑사원 공개 모델뿐이고, 우리는 이미 그것을 쓴다.

### 13.1 LG 사내 도입 방향성 (IR 제시용) `[확정: 문규남 11-03]`

원칙: **필요한 기능은 지금 우리가 직접 구현한다. 우리는 임직원이 아니라서 사내 도구에 연동하지 못했다. 그 연동은 실제 사내에서 쓸 때를 위한 열린 방향성으로 제시한다.**

| 지금 (구현 · 시연) | 사내 도입 시 (방향성 제시) | 근거 |
|---|---|---|
| 처리 완료 추적 · 리마인드 · 행동형 에이전트를 개인 메일 계정 위에서 단독으로 동작 | 같은 행동을 MCP로 열어 에이전틱웍스 같은 사내 에이전트 플랫폼에 붙인다. a:xink가 아침에 알려 준 일이 실제로 끝났는지 완료 체크까지 추적하는 보완 역할 | 에이전틱웍스는 MCP 방식으로 기존 서비스를 연동한다(기사 확인). 행동 정의를 백엔드 레지스트리 한 곳에 두고 웹 · 버튼 · MCP가 같이 쓴다(D37 · D43) |
| 엑사원 공개 모델(EXAONE 3.5 7.8B)을 직접 운영 | 사내에서 서빙하는 엑사원(챗엑사원과 같은 계열)으로 모델 위치만 바꾼다 | 모델 위치는 `OLLAMA_BASE_URL` 환경 변수로 바뀐다. 사내 서빙의 API 형식이 다르면 연결 코드 하나를 더 쓴다 `[미확인: 사내 서빙 형식]` |
| 라이선스: 공개 모델은 비상업 라이선스, 교육 과제 시연 범위 | LG 임직원용으로 개발하는 서비스이므로 LG가 보유한 사내 엑사원을 쓴다 | 문규남 11-03 판단. Q&A에서 상용 라이선스 질문이 나오면 이 답을 쓴다 |

발표 문구:

- "지금 시연한 기능은 개인 메일 위에서 혼자 돌아갑니다. LG 사내에 들어가면 같은 기능을 MCP로 열어 에이전틱웍스 같은 사내 에이전트 플랫폼에 붙일 수 있게 설계했습니다."
- "챗엑사원과 같은 엑사원 계열 모델을 씁니다. 사내에서는 사내 엑사원으로 주소만 바꾸면 됩니다. AI 처리 과정에서 외부로 나가는 데이터는 없습니다."

말하지 않는 것:

- "a:xink와 연결된다 · 연결해서 시연한다" — 공개된 연결 통로가 없고, 우리는 연동하지 않았다.
- "MCP로 연동된다" — MCP 서버는 P2이고 아직 구현하지 않았다. "구조를 갖췄다 · 설계했다"까지만 말한다.

MCP 발표 범위 `[확정: 문규남 · 이재운 11-04, PR #5 리뷰]`: 시연하지 않고 방향성으로 제시한다. 여유가 되면 MCP 서버를 실제로 연결해 본 성공 사례(캡처 등)를 발표 자료에 첨부한다(BE-17, P2). 연결 상대로 외부 AI를 쓰면 메일 데이터가 외부로 나가므로, 확인은 로컬 도구(MCP Inspector 등)로 한다 `[제안]`.
- "챗엑사원을 돌린다" — 우리가 돌리는 것은 공개 모델이다.
