# 에이전트 제안 카드 규칙 (초안, 2026-11-10)

> 상태: 초안 · 팀 리뷰 대기 · 작성: 문규남 · 작업 번호: PL-15 · 결정: `docs/00_common/decisions.md` D50
> 근거: D9 · D13 · D27 · D35 · D37 · D41 · D44 · D48, 기획 detail 4 · 5 · 6 · 8절, AI detail 2 · 3절(행동 T01~T14), wireframe 13-4절(에이전트 패널), `refs/benchmark.md`(Gmail 넛지 · Superhuman 후속 리마인드 · Copilot in Outlook · a:xink 데일리 브리핑)
> 표기: `[확정]` 팀 결정 · `[제안]` 팀 확인 필요 · `[결정 필요]` 정하지 않음 · `[미측정]` 수치 확인 전

## 1. 왜 만드는가

지금 에이전트 패널은 사용자가 말을 걸어야만 움직인다. 그래서 대시보드나 리마인더와 비교했을 때 에이전트만의 역할이 잘 보이지 않았다. 제안 카드는 이 점을 바꾼다. 사용자가 패널을 열면 에이전트가 먼저 "이 업무를 지금 챙겨야 한다"고 알려 주고, 바로 누를 수 있는 다음 행동을 함께 보여 준다.

- **Catch**: 놓치기 쉬운 업무를 규칙으로 찾아 카드로 띄운다.
- **End**: 카드의 버튼은 이미 있는 행동(T01~T14)을 그대로 실행한다. 새 실행 경로를 만들지 않는다.

리마인더와는 역할이 다르다. 리마인더는 정해진 시각에 **알림을 보내는** 기능이고, 제안 카드는 패널을 열었을 때 **다음 행동을 제안하는** 기능이다. 카드는 알림을 따로 보내지 않는다. 그래서 알림 수가 늘지 않는다.

## 2. 지키는 원칙

1. **판정은 규칙이, 엑사원은 초안만 맡는다** `[제안]`. 카드를 띄울지는 업무 상태 · 기한 · 발신자 같은 저장된 값으로 백엔드가 판정한다. 엑사원은 사용자가 [초안 보기]를 눌렀을 때만 부른다. 노트북에서 엑사원은 한 통에 수십 초가 걸리기 때문이다.
2. **버튼은 등록된 행동만 부른다** `[확정]`(D27). 카드에만 있는 실행 경로는 만들지 않는다. 확인 규칙도 D37 그대로다. 조회 · 표시는 바로 하고, 1건 상태 변경은 바로 한 뒤 되돌리기를 보여 주고, 발송은 항상 미리보기와 확인을 거친다.
3. **숨겨도 누락되지 않는다** `[제안]`(D13). 카드를 숨겨도 업무는 대시보드와 리마인더에 그대로 남는다. 숨긴 카드는 다음 단계가 되면 다시 뜬다. 예를 들어 기한 임박 카드를 숨겼더라도 기한이 지나면 기한 지남 카드가 새로 뜬다.
4. **업무 하나에는 카드 하나만 띄운다** `[제안]`. 여러 조건에 걸리면 4절 순서에서 가장 앞선 카드 하나만 보여 준다.
5. **완료를 재촉하는 카드는 만들지 않는다** `[제안]`. "이 5건은 한꺼번에 완료할까요?" 같은 제안은 확인하지 않은 채 지우는 습관을 만들어 누락 0 목표와 어긋난다. 일괄 처리는 사용자가 말로 지시할 때만 한다(T03).

### 3.1 버튼 규칙

- **주 버튼은 업무 종류로 정한다** `[제안]`. 회신요청 · 자료제출요청 · 검토승인요청 · 수정재전송요청처럼 답장으로 끝나는 업무는 [초안 보기](T07)를 주 버튼으로 둔다. 조치요청처럼 답장으로 끝나지 않는 업무는 [메일 열기](메일 화면의 그 메일로 이동, 행동 아님)를 주 버튼으로 둔다.
- **버튼은 3개까지만 둔다**. 주 버튼 하나와 보조 버튼 둘이다. 그 밖의 동작은 카드의 ⋯ 메뉴에 넣는다. ⋯ 메뉴에는 [업무 아님] T10과 [이 제안 숨기기]가 들어간다.
- **[나중에]는 대시보드와 같은 메뉴를 쓴다**. 오늘 오후 · 내일 오전 · 다음 주 월요일 · 날짜 선택 중에서 고르면 T05 `until`이 정해진다(wireframe 11-2).
- **[초안 보기]는 패널 안에서 단계 표시를 거친다**(UX-D8). 3초가 넘으면 "엑사원이 초안을 쓰는 중… (최대 30초)"를 보여 준다. 초안이 나오면 [답장 화면에서 열기]로 메일 화면의 답장 작성으로 넘긴다. 보내지는 않는다(D48).
- **[완료] · [나중에] · [업무 아님]은 1건 상태 변경이다**. 확인 없이 바로 실행하고 결과 카드와 [실행 취소]를 보여 준다(D37). 실행 취소를 누르면 카드가 다시 뜬다.

### 3.2 카드가 사라지는 때

| 사용자가 한 일 | 카드 | 업무 |
|---|---|---|
| [완료] · [업무 아님] | 사라짐 | 완료 · 제외 (되돌리면 카드도 돌아옴) |
| [나중에] | 사라짐 | 나중에. 그 시각이 되면 R-나중에 알림이 가고, 조건에 맞으면 카드가 다시 뜸 |
| [초안 보기] 뒤 답장 발송 | 사라짐 | D48 완료 확인 시트를 따름. 아니오를 고르면 업무는 남고, 카드는 다음 단계에서 다시 뜸 |

| 아무것도 안 함 | 남음 | 그대로 |

### 3.3 캘린더 자동 등록 (D50 결정 6 · 8)

설정에서 '일정 참석 메일을 캘린더에 자동으로 넣기'를 켜 두면, 일정 참석 메일은 누르지 않아도 **CNE 앱 캘린더**에 들어간다. 기본은 꺼짐이다. Outlook 캘린더에는 넣지 않는다.

- **넣는 때**: 메일 분류가 끝났고, 메일 유형이 일정참석이며, 메일에 날짜와 시각이 함께 적혀 있고, 그 시각이 아직 오지 않았을 때. 메일 한 통에 일정 하나만 만든다.
- **넣지 않는 때**: 시각 없이 날짜만 있으면 넣지 않는다. 날짜만 있으면 마감 보정 시각 18:00으로 잘못 들어가기 때문이다. 이때는 ⑤ 카드의 [캘린더에 넣기]로 사용자가 시각을 확인하고 넣는다. 이미 지난 일정, 같은 메일로 이미 만든 일정도 넣지 않는다.
- **알리는 곳**: 알림을 새로 보내지 않는다(원칙 3). 대신 사용자가 놓치지 않게 세 곳에서 보여 준다.
  1. 에이전트 패널 결과 카드: "{11/12(수) 14:00} '{메일 제목}' 일정을 캘린더에 넣었어요" + [실행 취소]
  2. 캘린더의 그 일정: '자동' 표시 + [빼기]
  3. 다음 아침 알림: "자동으로 넣은 일정 {N}건" 목록 + 건마다 되돌리기
- **기록과 되돌리기**: 자동 등록도 `action_log` 한 줄로 남긴다(`source = calendar_auto`). [실행 취소] · [빼기] · 아침 알림의 되돌리기는 모두 같은 되돌리기(T04)이고, 일정을 지운 시각만 남긴다. 되돌린 뒤 다시 넣으면 새 기록이 생긴다.
- **일정 길이** `[확정: 문규남 11-10]`: 메일에 끝 시각이 있으면 그 시각까지, 없으면 시작부터 1시간이다.
- **업무와의 관계**: 일정을 넣어도 업무(참석 회신)는 미처리로 남는다. ⑤ 카드는 [참석 회신 초안]을 주 버튼으로 계속 보여 준다. 일정을 빼도 업무는 그대로다. [완료]와 [나중에]도 일정을 건드리지 않는다.
- **[업무 아님]으로 뺄 때** `[확정: 문규남 11-10]`: 그 메일로 **자동 등록된 일정**도 함께 뺀다. 업무가 아니라고 판단한 메일의 회의가 캘린더에 남아 있으면 안 되기 때문이다. 업무 제외와 일정 빼기는 **기록 한 줄**로 남기므로, 그 제외를 되돌리면 업무와 일정이 함께 돌아온다. 결과 카드는 "업무에서 뺐어요. 자동으로 넣은 일정도 뺐어요" + [실행 취소]다. 사용자가 직접 넣은 일정([캘린더에 넣기] · 말로 지시)은 사용자의 뜻이므로 빼지 않는다.
- **일정이 바뀌거나 취소된 메일**: 자동으로 고치거나 지우지 않는다. 같은 대화에 일정 변경 · 취소로 보이는 메일이 오면 카드로 알린다(P2).

## 4. 순서와 개수

1. 패널 위쪽 '제안' 영역에 카드를 위 표 순서(① → ⑥)로 쌓는다. 같은 종류 안에서는 기한이 이른 순, 기한이 없으면 받은 시각이 이른 순으로 놓는다.
2. 처음에는 3장까지 보여 주고 나머지는 "제안 {N}건 더 보기"로 접는다 `[제안]`. 카드가 너무 많으면 사용자가 읽지 않고 넘기게 되기 때문이다.
3. ②~⑤는 업무마다 카드 한 장이다. 업무마다 초안을 쓸 대상이 다르기 때문이다. ⑥은 여러 메일을 한 장으로 묶는다. 재촉(T14)이 여러 건을 한 번에 다루기 때문이다.
4. 카드가 하나도 없으면 "지금은 챙길 제안이 없어요"와 예시 명령 3개를 보여 준다. 예시 명령은 지금 패널에 있는 것을 그대로 쓴다.

- ✦ 에이전트 버튼 옆에 마지막으로 패널을 연 뒤 새로 생긴 카드 수를 점 배지로 보여 준다. 마지막으로 연 시각은 브라우저에 저장하고, 카드에 붙은 생성 시각과 비교한다.
- 리마인더 알림(R-기한 · R-나중에)을 누르면 지금처럼 메일로 가는 대신, 그 업무 카드가 맨 위에 펼쳐진 에이전트 패널을 여는 방안을 검토한다 `[결정 필요]`(UX 담당).
- 화면 읽기: 카드 영역은 목록(`role="list"`)으로 두고, 새 카드가 생겨도 소리 내어 읽지 않는다. 버튼을 눌러 생긴 결과만 기존 `role="status"` 영역에서 읽는다(design_system 6절).

## 6. 백엔드 · 데이터 `[제안]` (BE 확인 필요)

- **조회**: `GET /api/suggestions`. 요청이 올 때마다 DB에서 계산한다. 기한 상태를 응답할 때 계산하는 것(wireframe 11-2)과 같은 방식이고, 스케줄러 작업을 따로 만들지 않는다. 응답 예:

  ```json
  {"suggestions": [{
    "key": "due_soon:task:123",
    "rule": "due_soon",
    "created_at": "2026-11-10T09:12:00+09:00",
    "title": "김민준 팀장님 '견적 회신' 기한이 오늘 18:00이에요. 초안을 써 둘까요?",
    "task_ids": [123], "mail_ids": [45],
    "buttons": [
      {"label": "초안 보기", "action": "T07", "target": {"mail_ids": [45]}, "params": {"tone": "polite"}, "primary": true},
      {"label": "나중에", "action": "T05", "target": {"mail_ids": [45]}, "params": {"until": null}},
      {"label": "완료", "action": "T03", "target": {"mail_ids": [45]}, "params": {}}
    ]
  }], "more": 2}
  ```

- **숨기기**: `POST /api/suggestions/{key}/hide`. 새 표 `suggestion_hides`에 사용자 · 키 · 숨김 끝 시각(다음 R-아침, 1시간 미만이면 그다음 날)을 저장한다. 응답 대기 카드는 숨길 때 기다리던 메일 id도 저장해, 그 밖의 메일이 새로 기다림에 들어올 때만 다시 띄운다(구현: PL-16, `docs/30_backend/agent_api_contract.md` 4절). 키에 카드 종류가 들어가 있으므로 종류가 바뀌면 숨김이 풀린다.
- **실행**: 버튼은 지금 있는 행동 실행 경로(상태 변경 · 미리보기 · 실행 · 되돌리기 API)를 그대로 부른다. `action_log.source`는 사용자가 누른 것이므로 `ui`로 두고, `params_json`에 `"via": "suggestion:due_soon"`처럼 카드 종류를 남긴다. `source` 값을 늘리지 않아 DB 제약을 고치지 않아도 된다.
- **설정**: 임박 기준(기본 24시간), 상급자 경과 기준(기본 2시간), 카드 종류별 켜기 · 끄기는 P1 설정 화면에 둔다. 11/14에는 기본값으로 고정한다.

## 7. 측정 (발표에 쓸 수치)

제안 카드가 실제로 누락을 줄이는지 숫자로 보여 줄 수 있게, 처음부터 아래 값을 기록에서 셀 수 있게 만든다. 모두 `action_log`의 `via`와 `suggestion_hides`로 계산하고, 새 기록 표는 만들지 않는다.

| 지표 | 뜻 |
|---|---|
| 카드로 끝낸 업무 수 | 카드 버튼으로 완료 · 답장까지 간 업무 수 |
| 카드 수락률 | 띄운 카드 중 버튼을 누른 비율 (띄운 횟수는 조회 응답 로그로 셈) `[결정 필요]` |
| 숨김 비율 | 띄운 카드 중 숨긴 비율. 높으면 조건이 너무 넓다는 신호 |
| 기한 지남 카드 수 | 시연 데이터에서 임박 카드를 켠 경우와 끈 경우를 비교 `[미측정]` |

## 9. 시연 장면 (기획 detail 8절에 더할 후보)

1. 아침에 패널을 열면 기한 지남 1장, 임박 1장, 응답 대기 1장이 먼저 떠 있다(Catch).
2. 임박 카드에서 [초안 보기]를 누르면 엑사원이 초안을 쓰고, 답장 화면에서 보낸 뒤 완료 확인 시트에서 "예"를 누른다(End).
3. 응답 대기 카드에서 [재촉 메일 미리보기]를 누르고 미리보기를 확인한 뒤 보낸다(11/21 이후).
4. 이어서 기존 장면(말로 지시 · 되돌리기 · 외부 호출 0건)으로 넘어간다.

시연 데이터에는 기한 임박 회신 · 기한 지남 · 상급자 · ASAP · 일정 참석 · 3일 무응답이 한 건씩 있어야 한다(데이터 · 평가 파트).
