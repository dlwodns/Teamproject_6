> 작성 방식: 작성자의 아이디어를 Claude로 템플릿화해 초안을 잡고 구체화했다.

## 2. 발표 요지

- 과제: LG CNS 과제 4번 '미처리 메일 리마인더 봇'. 하루 100~200통 속에 묻힌 기한 있는 요청을 뽑아 기한 순으로 보여 준다. PC 웹, 11월 말까지 핵심 기능 동작 버전
- 니즈 4가지: 건별 '언제까지' 알림 · 중요도 = 상급자 발신 + 기한 · 회신 시 자동 완료 · 답장 초안/요약/번역
- 제약: 보안상 사내 메일 직접 연동 불가 → 연습용 더미 메일 사용(초기 400~500건, 최종 1,000~1,500건으로 발표)
- 개발: 규칙 판별 → 모호한 것만 AI 추출 → 대시보드. 화면 · 서버는 Next.js · TypeScript 검토 중. 1인 150통 기준 하루 입력 약 22만 · 출력 약 3만 토큰
- 고민 3가지: 회신했지만 일이 남은 경우의 완료 처리 · 정확도 확인 기준 · 범위(할 일 목록 + 완료 vs 알림까지)

## 4. 피드백

### 피드백 1 · 데이터셋 구성

- 내용: 메일 데이터셋을 직접 만들면 실제 형식 · 데이터 증강 등 고려할 것이 많다. 공개 메일 데이터셋을 최대한 찾아 쓰고, 영어뿐이면 실무와 비슷한 영어 데이터를 한국어로 바꿔 쓴다. 처음엔 20~30건으로 테스트하고 점점 늘린다. MailEx(EMNLP) 참고 추천
- 반영: 기존 더미 메일 계획을 유지하고, 공개 데이터셋은 비교용으로 쓴다 (D22)

### 피드백 2 · 처리 완료 기준

- 내용: 완료 체크 시 리마인드를 한 번 더 띄울지 사용자에게 묻는 방식 제안
- 팀 답변: 하루 150건 내외를 하나씩 누르는 부담 때문에 에이전트 칸을 두고 일괄 처리 방식을 기획 중이다
- 보충 설명: 일괄 처리가 아니라 완료 기준에 대한 말이다. 회신하면 일단 완료로 넘기되, 회신 후에도 이어서 할 업무가 남으면 리마인드하도록 설정할 수 있게 하면 좋겠다
- 반영: 회신 시 사용자에게 완료 여부를 확인하는 팝업을 띄운다 (D23)

## 5. 확인된 사실 (PRD 반영 후보)

- 실제 수신 테스트용 공용 Outlook 계정을 만든다 (Q1 · Q2)
- 범위는 메일로 한정한다 (Q3, PRD 제약과 일치)
- 이 화면이 메일 화면보다 먼저 보이는 첫 화면이다 (Q4, D20 · 와이어프레임 v2.0과 일치)
