## 1. 우선순위: 점수 배분이 꼭 필요한가

### 방식 비교

| 방식 | 원리 | 누락 위험 | 사례 |
|---|---|---|---|
| 가중합 점수제 | 기준별 점수를 더해 문턱값으로 P1~P3 | 높음. 한 기준이 약하면 다른 기준이 강해도 묻힌다(보상형) | Gmail Priority Inbox |
| 사전식 규칙 · 결정 트리 | 1순위 기준으로 먼저 나누고 같을 때만 다음 기준 | 낮음. 1순위 조건에 걸린 메일은 밀리지 않는다 | 응급실 트리아지(ESI) |
| 버킷(칸) 분류 | 규칙에 맞는 메일을 칸에 나누고 칸별 개수 표시 | 중간. 다른 칸을 안 보면 놓친다 | Superhuman Split Inbox, Outlook Focused |
| 기한순 정렬(EDF) | 마감이 가까운 것부터 | 기한 없는 메일이 계속 밀린다 | SLA 큐 |
| 영향 × 긴급 매트릭스 | 두 축 등급을 표에서 찾아 우선순위 결정 | 낮음~중간 | ITSM, Zendesk SLA |

### 확인한 사실
- `[사실]` Gmail Priority Inbox는 로지스틱 회귀 점수를 쓰고 사용자별 문턱값을 둔다. 사용자가 고친 결과로 문턱값을 계속 맞춘다. 놓침(False Negative)이 잘못 올림보다 3~4배 많았다.
- `[사실]` Superhuman Split Inbox는 점수 없이 규칙으로 칸을 나누고, VIP 메일은 Important 칸에도 중복 노출한다.
- `[사실]` 응급실 트리아지는 위급도로 먼저 거르고, 과소분류를 피하려고 과대분류를 허용한다.
- `[사실]` Zendesk는 우선순위 등급별로 SLA를 두고, 같은 등급 안에서는 위반에 가장 가까운 것을 먼저 보여 준다.

### 현재 초안의 문제와 원인 `[추론]`
- P3 쏠림(할 일 60건 중 31건): 문턱값(70 / 40)이 임의로 정해졌고, 기준 하나만 해당하는 메일은 30점 근처에 머문다.
- 상급자 · 즐겨찾기 중복 가산: 둘 다 "중요한 발신자"인데 두 번 더한다.
- 회의 시간 변경이 P1: "해야 할 행동의 크기"를 보는 축이 없다.

### 권장안 `[추론]`
1. **0단계 · 할 일 여부:** 회신 · 제출 · 결재 요청은 '할 일', 시간 변경 · 공지 · 참고는 '확인만'으로 나눈다.
2. **1축 · 기한 상태:** 기한 지남 / 오늘 / 3일 내 / 그 이후 / 기한 없음
3. **2축 · 발신자 등급:** 상급자 · 즐겨찾기 · 대상자는 '핵심' 하나로 묶고, 나머지는 '일반'
4. **칸 안 정렬:** 마감 임박순, 같으면 받은 시각순. 재요청 · 긴급 표현은 점수로 더하지 않고 한 칸 위로 올린다(한 번만)
5. **노화 규칙:** 기한 없음 + 미처리 N일 경과 시 '3일 내' 칸으로 올린다(N은 팀 결정)
6. **안전망:** 어느 칸이든 '할 일'은 숨기지 않는다. 칸은 순서만 정한다

### 대시보드 예시 (미해결 건)

| | 핵심 발신자 | 일반 |
|---|---|---|
| 기한 지남 | 빨강 · 맨 위 고정 | 빨강 |
| 오늘 | 주황 | 주황 |
| 3일 내 | 노랑 | 노랑 |
| 이후 / 기한 없음 | 회색 + 경과일 | 회색 |
| 확인만 | 별도 탭 · 개수만 | |

칸마다 개수를 표시한다. 사용자가 칸을 옮긴 기록은 규칙 개선 로그로 남긴다.

## 2. 처리 완료 감지

### 확인한 사례

| 제품 | 감지 신호 | 자동 완료 | 한계 |
|---|---|---|---|
| Viva Insights Briefing | 받은 요청 · 내 약속 · 후속 조치 추출 | 아니오. 사용자가 Done | 탐지 방식 비공개, 현재 발송 중지 |
| SaneBox SaneReminders | 상대 회신 여부 | 예(리마인더 취소만) | 내용 충족 여부는 안 봄 |
| Inbox Zero (Reply Zero) | To Reply · Awaiting Reply 라벨 | 부분적. 새 회신이 오거나 내가 보내면 Follow-up 라벨 제거 | 라벨 기준 비공개 |
| Shortwave | AI 할 일 추출, Done · Todo | 아니오. 사용자가 Done | 사용자 승인 단계를 둠 |
| Superhuman, Copilot in Outlook, Gmail Gemini, Front, Hiver 등 | — | `[미확인]` | 문서 확보 실패 |

- `[사실]` 직접 확인한 범위에서 "요청을 실제로 처리했는지" 내용까지 보고 자동 완료하는 제품은 없었다. 자동 처리는 "회신이 생기면 리마인더 · 라벨 해제" 수준이다.
- `[사실]` 연구는 요청 · 약속 "탐지"에 집중돼 있다. Enron 기반 요청 탐지에서 인용문 · 서명을 걸러 작성자 문장만 보자 정확도가 72.3%에서 83.8%로 올랐다(Lampert 외, NAACL 2010). 메일 코퍼스가 바뀌면 탐지 성능이 크게 떨어졌다(Azarbonyad 외, WSDM 2019).
- `[미확인]` "회신이 요청을 충족했는가"를 직접 판정하는 연구는 찾지 못했다.

### 구현 방식 비교

| 방식 | 내용 | 잘못 완료(오탐) | 완료 놓침(미탐) |
|---|---|---|---|
| A. 스레드 매칭 | 같은 대화(Graph `conversationId`, 헤더 `In-Reply-To`)에 받은 뒤 보낸 내 메일이 있는지 | "확인 후 보내겠습니다"도 완료 처리 | 메신저 · 전화로 처리, 새 메일로 따로 보냄 |
| B. A + 첨부 규칙 | 파일 요청이면 회신에 첨부가 있어야 후보 | A보다 낮음 | 링크 공유, 인라인 이미지 |
| C. A + LLM 충족 판정 | 요청과 회신 본문(인용 제거)을 비교해 충족 / 부분 / 미충족 / 연기 | 모델이 "확인했습니다"를 충족으로 볼 수 있음 | 짧은 회신의 맥락 누락 |
| D. 사용자 승인 | 후보만 표시하고 사용자가 확인 · 일괄 완료 | 거의 없음 | 승인 피로 |

### 권장안 `[추론]`
- 1단계: A + B로 "완료 후보"를 잡고 확신도 3단계로 나눈다.
  - 높음(파일 요청에 첨부 회신, 요청 1개): 자동 완료 + "완료됨 · 되돌리기" 표시
  - 중간(회신은 있으나 요청이 여러 개이거나 첨부 없음): '완료 후보' 묶음 → 사용자가 일괄 확인
  - 낮음(회신 없음): 미처리 유지
- 모든 자동 완료에 매칭한 보낸 메일을 근거로 기록해 보여 준다.
- 2단계: C(LLM 판정)는 '중간' 등급 정렬에만 먼저 쓰고, 측정 후 자동 완료 권한을 준다.
- 더미 데이터에 **보낸 메일(내 회신)**이 없으므로 추가해야 한다. 보류성 회신, 요청 2개 중 1개만 답한 회신, 제목이 바뀐 회신, 새 메일로 보낸 파일을 일부러 넣는다.

## 3. 계정 연결 방식

| 서비스 | 비밀번호 IMAP (서버 대리 로그인) | 앱 비밀번호 + IMAP | OAuth |
|---|---|---|---|
| Outlook.com (개인) | **불가** — 2024-09-16부터 기본 인증 실패 `[사실]` | `[미확인]` — 공식 안내에 IMAP 언급 없음 | **가능** — Graph Mail.Read, IMAP XOAUTH2 `[사실]` |
| Microsoft 365 (회사) | 불가 — 2022-10-01 폐지 `[사실]` | 불가 — 기본 인증 차단 시 앱 비밀번호도 차단 `[사실]` | 회사 관리자 승인 필요 (LG CNS는 외부 연동 불가) |
| Gmail (개인) | 불가 | 조건부 가능 — 2단계 인증 필수 `[사실]` | 가능 — 단 gmail.readonly는 제한 범위라 외부 공개 시 심사 `[사실]` |
| Gmail (Workspace) | 불가 — 2025-05-01 종료 `[사실]` | 회사 · 학교 계정은 막힐 수 있음 | 관리자 정책에 따름 |
| 네이버 | `[미확인]` | `[미확인]` | `[미확인]` |

- 서버 대리 로그인의 추가 문제: 본 계정 비밀번호 원문을 보관해야 한다. 유출 시 계정 전체가 넘어간다. OWASP는 비밀번호를 복호화 가능한 형태로 저장하지 말라고 권한다. 2단계 인증 계정은 로그인할 수 없다.
- 권장 `[추론]`: 데모와 실사용 모두 OAuth — Microsoft Entra 앱 등록(로그인 대상 `consumers`) + 위임 권한 Mail.Read + Python MSAL + Graph. 앱 비밀번호는 Gmail · 네이버 개인 계정용 보조 수단으로만 검토한다.
- 직접 확인할 것: 팀 Outlook 테스트 계정으로 앱 비밀번호 IMAP 접속이 되는지 한 번 시도해 본다.
