### 04 아키텍쳐_6팀
드라이브 문서와 v2의 차이(v2 0절 표 그대로):
- 처리 상태: 미처리 / 처리 완료 → 미처리 / 완료 / 제외 + 나중에 처리
- 메뉴: 미처리 · 처리 완료 · 계정 → 미처리 · 완료 · 전체 + 설정
- 줄 클릭: 원문 바로 열기 → 상세 패널 → 원문 열기 / 상태 선택
- 보조 알림 구조, 자동 동기화 반영
- 기술 스택: 미정 → Python · FastAPI · APScheduler · SQLite
- 메일 서비스: 미정 → Outlook 우선
- 성공 기준 테스트 10건(입력 · 기대 결과) 추가

v3에서 바뀔 점(PRD v2 · 인터뷰 반영)은 `docs/handoff.md` '구조도 v3에 반영할 것'에 있다. 드라이브에는 "v3 작성 예정" 한 줄만 적어 둔다.

### 01 PRD_6팀
- `docs/PRD.md` v2.2 본문을 그대로 옮긴다. `[인터뷰]` `[결정]` `[미정]` 표시는 유지한다
- v1에서 바뀐 곳: Q1(팀장, 100~200통) · Q2(장면 3개) · Q3 · Q4(본문 추출 · 우선순위 · 회신 자동 완료 목표) · Q5(Outlook 3단, PC 기본) · Q6(더미 100건 재현율) · 필요 데이터 · 제약(사내 메일 불가 → 더미) · 다음 단계
- v1의 숫자 불일치(Q6 '10건' / 한 단락 '30~50건')는 '더미 메일 테스트셋 재현율'로 바꿔 없앴다
- 2026-10-22 결정(`[결정]`): 전체 방향은 인터뷰를 따름 · 자동 처리 완료 추구, 안 되면 묶어서 처리 · 우선순위 주 기준(상급자 · 임박한 기한 · 즐겨찾기 · 대상자, 기업체는 검토 중) · 계정 연결은 실사용용 · 더미 메일 100 → 400~500 → 1,000건(테스트셋 · 검증셋) · 외국어 메일 번역 · 요약
