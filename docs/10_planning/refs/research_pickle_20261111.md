# 조사 정리 · 피클(Pickle) 개인 AI 에이전트는 어떻게 만들었나 (2026-11-11)

> 목적: "CNE 에이전트를 피클 앱처럼" 만들기 위해, 피클이 무엇을 하는지와 어떻게 만들었는지를 공개 자료로 확인한다. 계획과 명세는 `../agent_pickle_plan.md`에 있다.
> 방법: 앱스토어(한국 · 미국) 개발자 설명, YC 회사 페이지, 국내외 기사 · 체험기 6건, GitHub `pickle-com` 조직의 공개 저장소를 직접 읽었다. 사이트별로 읽은 범위는 9절에 적었다.
> 표시: `[사실]` 원문에서 확인 · `[보도]` 기사나 체험기에만 있음(단일 출처면 따로 적음) · `[제안]` 우리 해석 · `[미확인]` 확인하지 못함.

## 1. 한 줄 결론

피클은 **코드를 공개하지 않은 상용 앱**이다. 어떤 프레임워크로 만들었는지 회사가 밝힌 적이 없다. 11-10 팀 공유안이 가정한 LangGraph · Browser-Use · MCP · Whisper를 피클이 쓴다는 공개 근거는 **하나도 찾지 못했다** `[미확인]`. 공개된 것은 비밀번호 · 토큰을 격리 보관하는 부품 하나(`credential-enclave`)와 에이전트 평가 도구 포크 하나(`tau2-bench`)뿐이다 `[사실]`. 그래서 벤치마킹은 "피클의 코드를 따라 만들기"가 아니라 **"피클의 사용자 경험과, 공개된 설계 원칙과, 보도된 실패 사례를 보고 우리 구조로 다시 만들기"** 가 맞다 `[제안]`.

## 3. 사용자가 보는 기능

### 3.1 시키면 끝까지 한다

- **입력**: 채팅, 음성, 피클에게 전화 걸기 세 가지다 `[사실]`.
- **웹 작업**: 휴대폰이 아니라 회사 클라우드에 있는 피클 전용 브라우저에서 사람처럼 누르고 입력한다. 그래서 휴대폰에 로그인돼 있어도 피클 쪽에서 다시 로그인해야 한다 `[사실: 도움말 인용]`. 진행 화면을 실시간으로 볼 수 있고, 사용자가 언제든 그 브라우저를 직접 열 수 있다 `[사실]`. 캡차가 나오면 사용자가 브라우저를 열어 풀고 "다 했어요"를 누른다. 인증번호는 채팅의 카드에 넣는다 `[보도]`.
- **전화 대행**: 피클 번호로 고객센터 · 식당 · 병원에 전화한다. 통화 내용이 채팅창에 글로 올라오고, 끝나면 결과를 요약해 준다 `[사실]`. 상대에게 AI라고 밝히고 통화가 기록된다고 알린다는 것이 약관 내용이다 `[보도]`.
- **연결 서비스**: 계정 권한(구글 · 마이크로소프트 · 슬랙 · 노션), 휴대폰 데이터(연락처 · 캘린더), 사이트 로그인(쿠팡 · 코레일 · 정부24 등), 메일(네이버 메일은 IMAP과 앱 비밀번호) 네 가지 방식으로 60여 개를 붙인다 `[보도]`.
- **작업 카드**: 맡긴 일마다 진행 중 · 대기 · 완료 · 실패 상태가 붙은 카드가 생긴다. 앱을 닫아도 작업은 계속된다. 진행 중인 작업은 취소할 수 있지만 이미 보낸 예약 · 결제는 되돌리지 못한다 `[보도: note.com 도움말 인용]`.

### 3.2 먼저 말을 건다

- 메일과 일정을 보고 피클이 처리할 수 있는 일을 **먼저 제안**한다. 예: 분실 택배 청구, 안 쓰는 구독 해지, 자동차 등록 갱신 `[사실]`.
- 매일 아침 **Morning Summary**(날씨 · 일정 · 밤사이 메일 정리)를 보낸다. 이것은 하루 사용량을 쓰지 않는다 `[보도]`.
- 할 일을 무시하면 다시 알려 주고, 시키지 않았는데 "인터뷰 질문지 회신이 아직 안 왔다"고 알려 준 사례가 있다 `[보도: 체험기]`.
- **반복 작업**(매일 · 매주 · 매월)을 맡길 수 있다. 하루 한도를 다 쓰면 예약된 작업은 건너뛴다 `[보도]`.
- 매진된 열차에 취소표가 나오면 알려 주고, 요청하면 바로 예매한다 `[사실]`.

### 3.3 기억한다

- 대화에서 알게 된 것을 기억하고, 앱의 'Memories'에서 보고 고치고 지울 수 있다 `[보도]`.
- 회사 소개는 "사용자마다 지속되는 기억을 가진 전용 에이전트"다 `[사실: YC]`. 구현 방식은 밝히지 않았다.
- 메일 근무표에서 직업을, 메일 · 넷플릭스 프로필 · 연락처를 조합해 자녀 이름과 생일을 알아냈다는 사례가 보도됐다 `[보도]`. 편하다는 반응과 불편하다는 반응이 함께 있다.
- 연결을 끊어도 이미 가져온 대화와 기억은 자동으로 지워지지 않는다 `[보도: 도움말 인용]`.

### 3.4 확인을 받는다

- "돈이 들거나 쉽게 되돌릴 수 없는 일은 먼저 승인을 받는다"가 공식 설명이다 `[사실]`. 결제 전에 무엇을 얼마에 사는지 보여 주고, 금액이 처음 안내보다 늘면 다시 묻는다 `[보도]`.
- 다만 사용자가 상품과 금액을 정해 실행을 요청하면 그 요청을 동의로 보고 다시 묻지 않을 수 있다고 도움말에 적혀 있다 `[보도: note.com]`. 체험기 필자는 첫 대화에서 "전화 · 메시지 · 메일 발송은 반드시 내 승인을 받고 해"라고 지시해 두라고 권한다 `[보도]`.
- 공식 고지: "피클은 부정확하거나 예상과 다른 작업을 할 수 있다. 큰 작업은 중간에 확인하라" `[사실]`.

### 3.5 피클끼리 대화한다

친구도 피클을 쓰면 두 피클이 서로 대화해 빈 시간을 맞추고 장소를 고르고 예약까지 한다. 그 대화는 언제든 볼 수 있다 `[사실]`. 회사는 이것을 'A2A 네트워크 효과'로 성장 전략에 쓴다 `[사실: YC]`.

## 4. 어떻게 만들었나 — 공개된 것만

| 부분 | 확인된 것 | 근거 |
|---|---|---|
| 언어 모델 | 개인정보처리방침에 응답을 만드는 제공자로 구글 · 오픈AI · 앤트로픽 · xAI가 적혀 있다. 즉 자체 모델이 아니라 **여러 외부 모델을 골라 쓴다** | 준이아빠블로그가 방침 인용 `[보도]` |
| 브라우저 | 자체 클라우드 브라우저. 기본 저장은 미국, 일본 계정의 브라우저와 로그인 상태는 도쿄에 둔다. 어떤 브라우저 자동화 도구를 쓰는지는 밝히지 않았다 | note.com `[보도]` · `[미확인: 도구]` |
| 결제 | Link by Stripe | 미국 앱스토어 `[사실]` |
| 비밀값 보관 | **credential-enclave**(Rust, Apache-2.0, 11/10 갱신). 사용자의 OAuth 토큰 · 앱 비밀번호 · 카드 · 일회용 비밀번호 시드를 AWS Nitro Enclave라는 격리 실행 환경 안에만 둔다. 운영자 서버도 평문을 보지 못한다. 방식은 둘이다. ① forward: 서버가 "구글에 이 요청을 보내 달라"고 하면 격리 환경이 토큰을 붙여 보내고 응답만 돌려준다. 토큰은 밖으로 나가지 않는다. ② release: 사이트 로그인처럼 값을 직접 넣어야 할 때만 한 칸씩 꺼내 주고, 그 뒤로는 보호하지 않는다고 스스로 적었다. 모든 사용은 **실행 전에** 지울 수 없는 로그 저장소(S3 Object Lock, 365일)에 먼저 적고, 적힌 것을 확인한 뒤에야 실행한다 | GitHub README · docs/enclave.md `[사실]` |
| 연결 대상 | 위 저장소에 적힌 제공자: Google, Microsoft, Slack, Notion, X, Link, Granola, Mercury, NAVER Mail | 같은 저장소 `[사실]` |
| 평가 | **tau2-bench** 포크(원본 sierra-research). 고객 응대 에이전트를 정책 · 도구 · 과업으로 시험하고, 사용자 역할을 하는 시뮬레이터와 여러 턴 대화한 뒤 **최종 데이터 상태와 행동**으로 채점한다. 피클이 고친 부분은 README에서 찾지 못했다 | GitHub `[사실]` · `[미확인: 피클 수정분]` |
| 앱 · 서버 · 오케스트레이션 | 공개되지 않았다. credential-enclave도 "앱은 아직 오픈소스가 아니다"라고 적었다 | `[사실]` |
| Glass | 데스크톱 비서 Glass 저장소는 지금 404다. 조직의 공개 저장소는 위 두 개뿐이다 | GitHub 조직 페이지 `[사실]` |

**알 수 있는 설계 원칙** `[제안: 위 사실에서 읽은 것]`

1. 모델은 바꿔 끼운다. 한 회사 모델에 묶지 않는다.
2. 비밀값은 모델과 일반 서버 밖에 둔다. 모델은 "구글에 이 요청을 보내 줘"까지만 말하고, 토큰을 붙이는 일은 별도 부품이 한다.
3. 행동은 실행 전에 먼저 기록한다. 기록이 안 되면 실행하지 않는다.
4. 에이전트 품질은 한 문장 해석이 아니라 여러 턴 대화 뒤의 최종 상태로 잰다.

## 5. 보도된 실패 사례 (교훈용)

D50 결정 7에 따라 피클의 보안 수준을 단정하지 않는다. 아래는 보도된 사실과 회사 반응만 옮긴다.

| 날짜 | 사례 | 근거 |
|---|---|---|
| 10/27 전후 | 한 사용자의 피클이 요청 없이 근처 식당 여러 곳에 전화했다. 이유를 묻자 "아침 브리핑을 준비하던 중 자체 판단으로 했다"고 답했다(AI의 자기 진술) | 준이아빠블로그 `[보도]` |
| 10/29 | 일본 여행 유튜버가 호텔 조건을 물었을 뿐인데 피클이 호텔에 두 번 전화했고, 두 번째 통화에서는 AI라고 밝히지 않았다는 보도. 대표가 X에서 사과하고 "전화 전 확인"과 "처음에 AI라고 밝히기"를 필수 정책으로 했다고 전해진다 | note.com · 폭스씨지 `[보도]` · 대표 게시물 원문 `[미확인]` |
| 11/9 | 사용자가 말하지 않은 자녀 이름 · 생일을 메일과 연락처를 조합해 알아냈다는 보도 | 준이아빠블로그 `[보도: 매체명 미기재]` |
| 체험기 | 코레일은 로그인 단계, SRT는 좌석 선택 단계에서 막혔다. 워크숍 장소 3곳 중 1곳의 주소와 가격이 틀렸다. 쇼핑 뒤 네이버에서 해외 IP 로그인 알림이 5통 왔다(필자 추정: 피클 브라우저 접속) | 준이아빠블로그 `[보도]` |

**우리에게 주는 교훈** `[제안]`

- "알려 주기"를 준비하는 과정에서 **행동이 실행되면 안 된다.** 식당 전화 사례는 먼저 알리는 기능과 실행하는 기능이 한 경로에 섞였을 때 생긴다. CNE의 제안 카드 계산은 읽기만 하도록 못 박아야 한다.
- 실행 전 확인은 **프롬프트 지시가 아니라 코드 경로**로 강제해야 한다. 피클 사용자에게 "첫 대화에서 승인받으라고 시켜 두라"고 권하는 상황 자체가, 확인이 모델 판단에 맡겨져 있을 수 있다는 신호다. CNE의 D37(발송은 항상 미리보기와 확인)은 이미 코드 경로다.
- 기억은 **사용자가 보고 지울 수 있어야** 하고, 메일에서 몰래 추론한 개인 사실은 저장하지 않는 편이 업무용 도구에 맞다.
- 남의 웹사이트를 조작하는 방식은 상대가 막으면 끝난다(코레일). 사내 시스템에 붙을 때도 화면 조작보다 공식 API · MCP가 안정적이다.

## 6. 따라 만들 때 참고할 오픈소스

피클 코드가 없으므로, 같은 일을 하는 공개 프로젝트를 참고한다. **CNE에 가져와 쓰자는 목록이 아니라** 설계를 볼 목록이다. 실제 도입 여부는 계획 문서 4절에서 정한다.

| 하고 싶은 것 | 참고할 것 | 본 내용 | 확인 정도 |
|---|---|---|---|
| 비밀값을 모델과 떼어 두기 | pickle-com/credential-enclave (Apache-2.0) | 위 4절. forward 방식과 "실행 전 기록" | 저장소 직접 읽음 `[사실]` |
| 에이전트 여러 턴 평가 | sierra-research/tau2-bench (MIT, 피클도 포크) | 정책 · 도구 · 과업, 사용자 시뮬레이터, 최종 상태로 채점 | README 읽음 `[사실]` |
| 먼저 알리기 · 예약 실행 | openclaw/openclaw (MIT, 자체 호스팅 개인 에이전트) | 내장 스케줄러로 한 번 · 반복 · cron · 웹훅 실행, 늘 지킬 지시를 작업 폴더 파일(`AGENTS.md`)에 두고 모든 대화에 넣음. "들어오는 메시지는 믿을 수 없는 입력으로 다루라", "샌드박스를 안 켜면 도구가 호스트에서 돈다"고 경고. 추론으로 후속 약속을 만들던 기능은 2026.8.1에서 뺐다 | README · 문서 일부 읽음 `[사실]`, 승인 · 권한 문서는 못 읽음 `[미확인]` |
| 음성 · 회의 맥락 | Glass by Pickle | D54 그대로. 지금 저장소 404 | `[미확인: 현재 코드]` |
| 화면 조작 | Browser-Use 등 | D50 결정 2로 쓰지 않음. 이번 조사에서 피클이 쓴다는 근거도 없음 | 조사 안 함 |

## 7. 공유안 가정과 사실 대조

| 11-10 공유안 가정 | 이번에 확인한 것 |
|---|---|
| 피클은 LangGraph로 단계를 조율한다 | 근거 없음 `[미확인]` |
| 피클은 Browser-Use로 웹을 조작한다 | 자체 클라우드 브라우저를 쓰는 것은 맞다. 어떤 도구인지는 근거 없음 |
| 피클은 MCP로 서비스를 붙인다 | 근거 없음. 공개된 연결 방식은 OAuth 토큰 대리 호출(forward)과 사이트 로그인(release) |
| 피클은 Whisper로 음성을 알아듣는다 | 근거 없음. Whisper는 D54의 Glass 쪽 이야기다 |

## 8. CNE와 나란히 보기

| 피클 | CNE 지금 | 차이 |
|---|---|---|
| 생활 전반(쇼핑 · 예약 · 행정) | 회사 메일 업무의 처리 완료 추적 | 범위가 다르다. CNE는 좁고 깊다 |
| 외부 모델 여러 개 | 엑사원 API 기본, 로컬 7.8B 옵션(D51 · D52) | 둘 다 교체형. CNE는 엑사원 한 계열 |
| 클라우드 브라우저 · 전화로 실행 | 등록된 행동 T01~T15만 실행(D27) | CNE는 화면 조작 없음(D50 결정 2) |
| 메일 · 일정 기반 먼저 제안, 아침 요약 | 제안 카드 6종 · R-아침(D50) | 거의 같다. CNE는 규칙으로 판정, 모델 호출 없음 |
| 승인: 돈 · 되돌릴 수 없는 일 | 발송은 항상 미리보기와 확인(D37), 자동 실행 4조건(D50 결정 8) | CNE가 더 좁고 코드로 강제 |
| 작업 카드: 진행 중 · 대기 · 완료 · 실패 | 결과 카드 + 실행 취소 | CNE에는 모아 보는 '기록' 화면이 아직 없다 |
| Memories(보기 · 고치기 · 지우기) | 상급자 · 즐겨찾기 연락처, 내 직책 · 배포 목록, 항상 중요 규칙(T11)이 각각 따로 있다 | CNE에는 한곳에서 보는 화면이 없다 |
| 반복 작업 | 없음(T09는 알림 시각 설정만) | 새로 필요 |
| 피클끼리 일정 조율 | 없음 | 하지 않는다(계획 문서 4절) |
