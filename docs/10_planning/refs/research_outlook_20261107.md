# 조사 정리 · Outlook 메일 읽기 · 쓰기 화면 구성 (2026-11-07)

> 목적: 메일 화면 v3.2(와이어프레임 13-5 · 13-7, `../../20_frontend/decisions.md` UX-D13~UX-D16)에서 Outlook 받은 메일 보기 · 새 메일 쓰기 구성을 가져오는 근거를 남긴다.
> 방법: PC 화면을 MCP로 읽지 못해(PC 화면 · Outlook 앱을 읽는 연결 도구가 없음) **사용자 제공 스크린샷 2장**으로 확인했다 — ① 받은 메일 보기(새 Outlook, 한국어 화면) ② 새 메일 쓰기(왼쪽 폴더 창 · 가운데 목록 · 오른쪽 작성 창).
> 개인 정보: 스크린샷 속 실명 · 메일 주소 · 인증 코드 · 서비스 이름 · 계정 이름은 옮기지 않았다(`발신자 이름<주소>`처럼 일반화). 원본 이미지는 레포에 올리지 않는다(`.gitignore`의 실제 메일함 캡처 규칙과 같음).
> 표시: `[사실]` 스크린샷에서 확인 · `[제안]` 해석 · 권장 · `스크린샷에 없음` 화면에 보이지 않아 동작을 확인하지 못함

## 1. 받은 메일 보기 (스크린샷 ①)

| 영역 | 요소 | 기능 | 근거 | 우리 화면 |
|---|---|---|---|---|
| 맨 위 | 제목 + 오른쪽 '이 전자 메일 요약' 버튼 | AI(Copilot) 메일 요약 | `[사실]` 버튼 위치 · 문구. 요약 결과 모양은 스크린샷에 없음 | **같은 자리에 [메일 요약]**(UX-D15). 결과는 본문 위 카드 `[제안]` |
| 보낸 사람 줄 | 사진 자리(동그라미) · `발신자 이름<주소>` · 아래 '받는 사람: (수신자 칩)' · 오른쪽 날짜 시각(요일 · 오후 h:mm) | 누가 · 누구에게 · 언제 | `[사실]` | 그대로 + 이름 옆 플래그 칩(UX-D13) |
| 오른쪽 위 동작 | 반응(웃는 얼굴) · 회신 · 전체 회신 · 전달 · 앱 · ⋯ | 반응 · 답장 · 전달 · 추가 기능 · 더 보기 | `[사실]` 아이콘 배치. ⋯ 메뉴 내용은 스크린샷에 없음 | [답장](주 버튼) + ⋯([나중에] · [제외]). 전체 회신 · 전달 P1, 반응 · 앱 뺌 `[제안]` |
| 본문 | 제목 · 안내 문장 · 강조된 코드 · 맺음 | — | `[사실]` | 본문 + 업무 근거 형광펜(UX-D16) |
| 본문 아래 | [회신] [전달] 버튼 | 다 읽은 자리에서 바로 답장 | `[사실]` | [답장] [나중에 ▾] [제외] (13-7 기존안과 같음) |

## 2. 새 메일 쓰기 (스크린샷 ②)

| 영역 | 요소 | 기능 | 근거 | 우리 화면 |
|---|---|---|---|---|
| 리본 탭 | 파일 · 홈 · 보기 · 도움말 · **메시지** · 삽입 · 텍스트 서식 지정 · 그리기 · 옵션 | 쓰기 도구 묶음 | `[사실]` | 뺌 — 탭 없이 한 화면 `[제안]` |
| 메시지 도구 막대 | 되돌리기 · 붙여넣기 · 서식 복사 · 글꼴 · 크기 · 굵게 · 기울임 · 밑줄 · 취소선 · 형광펜 · 글자 색 · 스타일 · 글머리 기호 · 번호 · 들여쓰기 · 줄 간격 · ⋯ · 받아쓰기 · 첨부 · 링크 · 서명 · (모임 · AI 도구 등 아이콘) · 중요도 높음(!) · 중요도 낮음(↓) · 민감도 · 암호화(자물쇠) · 인쇄 | 서식 · 삽입 · 표시 | `[사실]` 아이콘 배치. 일부 아이콘 이름은 툴팁이 없어 추정 `[제안]` | 서식 막대 뺌(템플릿이 형식을 맡음, UX-D5). 첨부만 P1 후보 |

| 목록 위 | 전체 선택 상자 · **중요 / 기타** 탭 · 정렬 방향 · 필터 · 정렬 | `[사실]` | 중요/기타 = 우리 업무/확인사항과 같은 역할(메일함에서 나눔) |

## 4. 가져오지 않는 것과 이유

| 요소 | 이유 |
|---|---|
| Outlook 파랑 · 아이콘 · 글꼴 | 화면 배치만 가져오고 색 · 아이콘 · 서체는 `design_system.md`(UX-D4) |
| 서식 막대 · 리본 | 사용자는 하고 싶은 말만 쓰고 템플릿이 인사 · 맺음 · 서명을 채운다(UX-D5) |
| 반응 · 앱 · 민감도 · 암호화 · 중요도 | 업무 처리(답장 · 완료 · 나중에)와 관계없음 |
| 보내기 자동 · 예약 P0 | 사용자가 눌러야만 보낸다(D48). 예약은 P1 |

## 5. 결론 `[제안]` → UX-D14로 채택

읽기는 **제목 + 요약 → 보낸 사람 줄 → 업무 → 본문 → 아래 버튼**, 쓰기는 **보내기 · 보낸 사람 → 받는 사람 · 참조 → 제목 → 본문** 순서를 Outlook 그대로 따른다. 사용자가 이미 익숙한 위치라 따로 배우지 않아도 된다(wireframe 2절 Outlook 레퍼런스 결정과 같은 이유).
