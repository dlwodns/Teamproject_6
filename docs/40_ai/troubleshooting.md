## AI-T1 · 1.2B 모델이 공지 메일에 할 일을 만들고 마감을 지어냄 (2026-10-24)

- 상태: 해결 · 발견: 문규남 · 해결: 문규남 · 리뷰: [미정] · 공동: — · 근거: eval/bench/exaone_20261024
- 증상: EXAONE 4.0 1.2B가 할 일이 없는 공지 메일 4통을 모두 '할 일 있음'으로 판단하고 마감일을 지어냈다.

- 재발 방지: 모델을 바꿀 때 같은 벤치(`eval/bench/`)로 먼저 비교한다.

## AI-T4 · 서버에서 7.8B를 올리면 메모리 한도에 걸려 원격 접속까지 끊김 (2026-11-02)

- 상태: 해결(우회) · 발견: 문규남 · 해결: 문규남 · 리뷰: [미정] · 공동: — · 근거: AI-D9
- 증상: dev-server-02(user41)에서 7.8B 모델을 올리면 VS Code Remote 연결까지 끊긴다.
- 원인: 계정 cgroup `memory.high`가 5 GiB이고 스왑이 없다. 7.8B Q4_K_M(약 5GB)과 실행 메모리가 한도를 넘는다.
- 해결: 엑사원은 PC ollama에서 돌리고 서버는 Unix 소켓 역방향 터널로 부른다(`scripts/exaone-pc.sh`).
- 재발 방지: 서버에서 7.8B · llama-server를 띄우지 않는다. 터널이 끊기면 서버 모델로 우회하지 않고 PC 터널을 다시 켠다.

## AI-T5 · 엑사원이 할 일 없는 회신 · 완료 보고에 '확인' 할 일을 만듦 (2026-11-03)

- 상태: 미해결 · 발견: 문규남 · 해결: [미정] · 리뷰: [미정] · 공동: 데이터 · 평가 · 근거: plan 4.2절
- 증상: 라우터가 엑사원으로 보낸 메일 중 할 일이 없는 메일에 '~ 확인' 할 일을 만들었다. 대부분 마감이 없다. 예: 'RE: [요청] 개발 서버 증설'(내 요청에 대한 완료 회신) → '증설 작업 검토', '[보고] 개발계 백업 주기 변경 완료' → '변경 완료 확인'. dev 7건 · test 5건. 정밀도가 dev 98.4% → 88.2%, test 87.0% → 78.9%로 떨어졌다.
- 원인: 추정. 프롬프트(`classify_v1`)가 '읽고 확인'과 '해야 할 일'을 구분하는 예시를 주지 않는다 `[불확실]`.
- 해결: 미정. 후보는 ① 프롬프트에 '내 요청에 대한 완료 회신 · 결과 보고는 할 일 아님' 예시 추가 ② 마감 없고 동사가 '확인'뿐인 할 일을 후처리로 거르기. dev에서 고치고 테스트셋으로 다시 잰다(AI-18).
- 재발 방지: 엑사원 경로 수정 뒤에는 Task 정밀도도 함께 본다(누락 0만 보면 놓친다).

## AI-T6 · 지원하지 않는 '메일 다 지워줘'를 제외 처리(T10)로 해석 (2026-11-03)

- 상태: 미해결 · 발견: 문규남 · 해결: [미정] · 리뷰: [미정] · 공동: — · 근거: plan 4.2절 · detail 4절
- 증상: 명령 테스트 C-024 '메일 다 지워줘'(기대: 지원 외 → 행동 없음)를 엑사원이 T10 제외 처리로 바꿨다. C-026 '보고서 건 정리 좀'(애매 → 되묻기)은 T01 오늘 요약으로 해석했다.
- 원인: 모델 경로가 허용 목록 안의 가장 가까운 행동을 고른다. '지원 외 · 모르겠음'을 고르는 예시가 부족하다 `[불확실]`.
- 해결: 미정. 삭제 · 전체 같은 위험 표현은 규칙 경로에서 먼저 '지원 외'로 막는 방안을 검토한다. T10은 백엔드 확인 대상인지 detail 3절과 맞춰 본다.
- 재발 방지: 명령 테스트에 지원 외 · 애매 사례를 늘린다(데이터 · 평가).
