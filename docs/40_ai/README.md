## 1. 엑사원이 맡는 역할

실서비스 AI는 엑사원 API의 **K-EXAONE 2.5**(`k-exaone_v2.5`, D51 · D52 · AI-D18)만 쓴다. 로컬 엑사원(3.5 7.8B, ollama)은 쓰지 않는다. 판단은 모두 엑사원이 하고, 계산 · 검증 · 실행은 코드가 한다(AI-D19).

| 기능 | 엑사원이 하는 일 | 코드가 하는 일 | 근거 |
|---|---|---|---|
| 메일 분석 (`POST /classify`) | 모든 메일을 판단한다: 할 일이 있나, 할 일마다 유형(6개) · 문구 · 기한 글자(본문 그대로) · 형식 · 보낼 곳 · 근거 인용, 메일 성격(요청 · 회신 · 공유 · 공지 · 기타), 긴급 · 재요청, 한국어 요약 한 문장. 프롬프트 `classify_v8.4`. 판단은 모델이 하고 코드가 바꾸지 않는다(AI-D19) | `ai/`: 사실만 읽는다(`conditions.py` 수신 방식 · 배포 목록 · 사내외), 기한 날짜 계산(`dates.py` 한국어 · 영어 · 일본어 · 시간대), 근거 인용이 본문에 있는지 검증(AI-D33), 우선순위, 칸. 모델이 실패하면 규칙으로 메우지 않고 503 → backend가 다시 부름 | D39 · AI-D19 · AI-D26 · AI-D27 · AI-D33 |
| 근거 다시 고르기 (`POST /evidence`) | 근거가 빈 업무에 근거 문장을 옮겨 적는다(`evidence_v1`, 메일을 연 뒤 1회) | 본문에 글자 그대로 있는지만 검증, 아니면 비움 | AI-D33 |
| 명령 해석 (`POST /agent/plan`) | 모든 지시를 먼저 읽고 `{action, target, params, source}`를 낸다(AI-D19, `agent_v1.10`). 행동은 레지스트리 목록(T01~T20) 안에서만 고른다 | 규칙 매칭 · 허용 목록 검증(`ai/`), 대상 해석 · 확인 정책 판정 · 실행 · `action_log` 기록(`backend/`) | D37 · D44 · `detail.md` 4절 |
| 요약 · 다듬기 · 번역 (`POST /summarize` · `/polish` · `/translate` · `/draft`) | 아침 요약 · 저녁 · 주간 회고 머리 문장(`assist_v4`, 강도 low), 메일 요약(mode=mail), 답장 칸 다듬기(`polish_v1`), 누를 때만 번역(`translate_v1`). 캐치봇은 초안을 만들지 않는다(AI-D24, `/draft`는 남아 있으나 캐치봇에서 부르지 않음) | 입력 개인정보 가리기(`backend/privacy/`), 숫자 · 건수 검사, 길이 검사 | D42 · AI-D24 · AI-D25 · AI-D31 |
| 문맥 기억 · 리마인더 신호 (`POST /memory/extract` · `/signals`) | 보낸 사람의 맡은 일 · 소속, 약속 · 기한 변경 · 해결 · 나에게 온 질문 | 근거가 본문에 없으면 버림, 날짜 계산 · 업무 번호 확인 | AI-D20 · AI-D23 |
| 음성 | 하지 않는다. 음성은 브라우저에서 글자로 바뀐 뒤 명령 해석과 같은 길을 탄다. 서버 `/stt`는 만들지 않았다(AI-8, 11-20) | 음성인식(브라우저, FE-8) | D29 |
| 하지 않기로 한 것 | 회신 필요 여부 판별(AI-17 제외, 11-22) · 초안 작성(AI-16 제외) · 초안 자동 저장(AI-40 제외) | — | D43 · AI-D24 |

- 엑사원에 맡기지 않는 것: 날짜 계산, 우선순위, 확인이 필요한지 판정, 처리 상태 변경, 기능 실행, 메일 발송 · 삭제. 답장 후 완료도 엑사원이 판정하지 않는다 — 답장을 보내면 백엔드가 같은 메일의 미완료 업무를 "완료할까요?" 팝업으로 묻고 사용자가 정한다(D48, D36 대체).
- 메일 본문은 에이전트 의도 파악에 넣지 않는다. 본문에 지시처럼 보이는 문장이 있어도 실행하지 않는다.
- 출력 형식 · 행동 목록 · 확인 정책은 `detail.md`, 호출별 입출력 · 강도 · 제한 시간은 `io_spec.md`가 기준이다. 칸 이름의 원본은 코드(`ai/app/schemas/` ↔ `backend/app/schemas/ai.py`)다.

## 2. 파트 역할

| 일 | 담당 | 근거 |
|---|---|---|
| 분류기 구현(조건 · 엑사원 호출 · 날짜 계산 · 근거 검증), 명령 해석, 요약 · 다듬기 · 번역 | AI | AI-1~AI-47 |
| 더미 메일 · 정답 라벨 · 명령 테스트 세트, 채점 실행 · 보고서 | 데이터 · 평가 | DE-1~DE-9 |
| 채점 결과를 보고 규칙 · 프롬프트 수정 | AI + 데이터 · 평가 공동 | D46 · AI-18 · DE-9 |
| 분류 체계(분류 5개 · 행동 유형 묶음) 정의 | 공동 — 유형 정의는 라벨 가이드(`docs/50_data_eval/label_guide.md`) · AI-D15 · AI-D17 | D15 · D39 |
| Claude · OpenRouter 사용 | `eval/`에서 보조 채점 · 실패 사례 분석 · 모델 비교만. 서비스 코드에 넣지 않는다 | D26 · D41 |

수정 순환: 데이터 · 평가가 채점 → 놓친 메일 · 오분류 목록 → 두 파트가 함께 원인(규칙 · 프롬프트 · 정답 라벨)을 보고 수정안 확정 → AI가 `ai/app/pipeline` · `ai/app/prompts`에 반영 → 데이터 · 평가가 같은 테스트셋으로 다시 채점.

## 3. 엑사원 API (11-14부터 서비스 기본)

서비스 · 평가 모두 엑사원 API의 `k-exaone_v2.5` 하나를 쓴다(D51 · D52 · AI-D18). 로컬 엑사원(`EXAONE-3.5-7.8B-Instruct-GGUF:Q4_K_M`, ollama)은 쓰지 않는다. 설정 · 운영 점검은 **`ai/README.md` 설정 · 운영 점검 절** 한 곳에 둔다. 요약:

| 항목 | 기준 |
|---|---|
| 호출 | `https://api.exaone.ai/v1/chat/completions`(OpenAI 호환), `temperature` 0, JSON 스키마 응답, 출력 상한 16,384토큰(AI-D24). 호출부 `ai/app/llm/client.py` — 평가 실행기도 같은 호출부 |
| 추론 강도 | 분류 high(11-19 #237), 요약 · 회고 · 번역 · 근거 다시 고르기 low, 그 밖은 `EXAONE_REASONING_EFFORT`(비우면 API 기본 max) |
| 제한 시간 | 대화형 `LLM_TIMEOUT_S` 120초, 백그라운드(분류 · 기억 · 신호) `LLM_BACKGROUND_TIMEOUT_S` 300초(backend 310초) |
| 속도 | FINAL TEST 메일 1통 중앙 25.5초 · 90% 81.6초(`docs/50_data_eval/scores.md` 16절). 분류는 백그라운드라 화면을 막지 않는다 |
| 한도 · 키 | 키당 하루 100회, 키 유효기간 30일(AI-D18). `EXAONE_API_KEY=키1,키2`로 여러 키를 차례로 쓴다(AI-47) |
| 라이선스 · 약관 | API 약관은 비상업적 이용만 허용(AI-D18, 11-13 확인). 기업 도입 때는 같은 호출부에 엔터프라이즈 LLM을 끼운다(D52 · D58). 키 여러 개로 한도를 넘겨 쓰는 것이 약관에 맞는지는 확인 불가 |
