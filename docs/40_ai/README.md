## 1. 엑사원이 맡는 역할

실서비스 AI는 엑사원(EXAONE 3.5 7.8B)만 쓴다. 엑사원은 판단이 필요한 좁은 일만 하고, 계산 · 실행은 코드가 한다.

| 기능 | 엑사원이 하는 일 | 코드가 하는 일 | 근거 |
|---|---|---|---|
| 메일 분석 (`POST /classify`) | 규칙으로 판단하지 못한 메일만 받아 할 일 여부 · 행동 유형 · 할 일 문장 · 기한 표현 · 본인 지목 여부를 JSON으로 낸다 | `ai/`: 규칙 판별 · 라우터, 날짜 환산(받은 날짜 기준, 시간 없으면 18:00), 우선순위, JSON 형식 검사 | D14 · AI-T2 |
| 에이전트 의도 파악 (`POST /agent/plan`) | 사용자 지시를 실행 계획 `{intent, args, confirm_message}`로 바꾼다. intent는 `backend/app/agent/tools/`에 등록된 이름만 쓴다 | `backend/`: 인자 검증, 사용자 확인, 실행, 실행 기록 | D27 · D34 |
| 음성 (`POST /stt`) | 하지 않는다. 음성은 글자로 바뀐 뒤 에이전트와 같은 길을 탄다 | 음성인식(브라우저 · 서버 Whisper 교체형) | D29 |
| 다음 단계 | 외국어 메일 번역 · 요약, 답장 초안, 회신의 완료 후보 판정 | 길이 검사. 완료 확정은 사용자 확인 팝업 | D12 · D23 |

- 엑사원에 맡기지 않는 것: 날짜 계산, 우선순위, 처리 상태 변경, 기능 실행, 메일 발송 · 삭제.
- 메일 본문은 에이전트 의도 파악에 넣지 않는다. 본문에 지시처럼 보이는 문장이 있어도 실행하지 않는다.
- 출력 필드 이름과 에이전트 1차 기능 목록은 `[제안]` 상태다. AI 파트에서 확정한다(AI-9 스키마와 함께).

## 2. 파트 역할

| 일 | 담당 | 근거 |
|---|---|---|
| 분류기 구현(규칙 · 라우터 · 엑사원 호출 · 후처리), 에이전트 의도 파악, 음성 | AI | AI-1~AI-9 |
| 더미 메일 · 정답 라벨, 채점 실행 · 보고서 | 데이터 · 평가 | DE-1~DE-8 |
| 채점 결과를 보고 규칙 · 프롬프트 수정 | AI + 데이터 · 평가 공동 | D36 · AI-10 · DE-9 |
| 분류 체계(행동 유형 목록) 정의 | 공동 `[미정: 정의서 위치]` | D15 |
| Claude 사용 | `eval/`에서 보조 채점 · 실패 사례 분석만. 서비스 코드에 넣지 않는다 | D26 |

수정 순환: 데이터 · 평가가 채점 → 놓친 메일 · 오분류 목록 → 두 파트가 함께 원인(규칙 · 프롬프트 · 정답 라벨)을 보고 수정안 확정 → AI가 `ai/app/pipeline` · `ai/app/prompts`에 반영 → 데이터 · 평가가 같은 테스트셋으로 다시 채점.

## 3. 엑사원 로컬 설치

팀 공통 모델은 아래 이름 하나로 고정한다(D35). 다른 이름이나 다른 압축 수준을 받으면 채점 결과를 비교할 수 없다.

```
hf.co/LGAI-EXAONE/EXAONE-3.5-7.8B-Instruct-GGUF:Q4_K_M
```

### 3-1. 필요 사양

| 항목 | 기준 |
|---|---|
| 메모리 | RAM 16GB에서 동작 확인(LG gram, CPU만 사용, 10/24 벤치) |
| 디스크 | 모델 파일 약 5GB `[미확인]` |
| GPU | 없어도 된다. 대신 메일 1통 약 25초 |

### 3-2. 설치 순서

1. Ollama 설치: https://ollama.com/download 에서 OS별 설치 파일을 받는다. 설치 후 백그라운드에서 실행된다. 실행 중이 아니면 `ollama serve`로 켠다.
2. 모델 받기:
   ```
   ollama pull hf.co/LGAI-EXAONE/EXAONE-3.5-7.8B-Instruct-GGUF:Q4_K_M
   ```
3. 받은 모델 확인: `ollama list` → 목록에 위 이름이 있다.
4. 동작 확인:
   ```
   ollama run hf.co/LGAI-EXAONE/EXAONE-3.5-7.8B-Instruct-GGUF:Q4_K_M "안녕하세요. 한 문장으로 답해 주세요."
   ```
   → 한국어 한 문장 응답. 첫 호출은 모델 로딩으로 약 10초 더 걸린다.
5. API 확인(서버 코드 · 채점기가 쓰는 길):
   - Windows PowerShell: `Invoke-RestMethod http://localhost:11434/api/tags`
   - macOS · Linux: `curl http://localhost:11434/api/tags`
   - → 응답의 `models` 목록에 모델 이름이 있다.
6. `.env` 설정: 루트 `.env.example`을 `.env`로 복사하고 아래 세 줄을 확인한다.
   ```
   LLM_PROVIDER=ollama
   OLLAMA_BASE_URL=http://localhost:11434
   EXAONE_MODEL=hf.co/LGAI-EXAONE/EXAONE-3.5-7.8B-Instruct-GGUF:Q4_K_M
   ```

### 3-3. 호출 조건 (벤치와 같게)

- `temperature` 0
- JSON 스키마를 `/api/chat`의 `format`에 넣는다(벤치 조건 B).
- 프롬프트에 메일 받은 날짜를 넣는다(AI-T2).
- 참고 구현: `eval/bench/exaone_20261024/bench_v2.ps1`의 `Call-Model` 함수.

### 3-4. 속도 기준값 (CPU, RAM 16GB, 10/24 벤치)

| 항목 | 값 |
|---|---|
| 첫 호출 모델 로딩 | 약 10초 |
| 메일 1통 | 약 25초 |
| 하루 100~200통 전부 | 약 42~83분 → 라우터로 엑사원에 보내는 메일을 줄이고 백그라운드로 처리한다 |

### 3-5. 주의

- 메모리가 모자라면 다른 프로그램을 닫는다. 작업 후 `ollama stop <모델 이름>`으로 모델을 내린다.
- 1.2B 모델은 쓰지 않는다(AI-T1).
- 모델 · 압축 수준을 바꿀 때는 `eval/bench/`의 같은 벤치로 먼저 비교하고, D35를 새 번호로 대체한다.
- `LLM_PROVIDER=openrouter`는 PC 사양이 모자랄 때의 대안이다. 메일이 외부 서버로 가므로 더미 · 합성 메일에만 쓴다. OpenRouter의 엑사원 모델 이름은 확인하지 못했다 `[미확인]`.
- 엑사원 라이선스(상업적 사용 조건)는 확인 전이다 `[미확인]`.
