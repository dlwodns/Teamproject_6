# AI 서비스 한눈에 보기 (팀원용, 2026-11-11 · 갱신 2026-11-27)

> 대상: AI 파트 밖의 팀원(기획 · FE · BE · 데이터). "ai 폴더가 무엇을 해 주고, 화면 어디에 쓰이며, 지금 어디까지 됐나"를 한 장으로 본다.
> 자세한 명세: `docs/40_ai/detail.md`(행동 목록 · 명령 해석) · `docs/40_ai/README.md`(역할) · `docs/30_backend/agent_api_contract.md`(에이전트 패널 계약). 작성: 문규남(AI 팀장)

## 1. 한 줄 요약

`ai/`는 backend와 따로 도는 작은 서버다(FastAPI, D34). backend가 HTTP로 메일이나 사용자 말을 보내면, 엑사원 API(K-EXAONE 2.5)가 판단하고 코드가 계산 · 검증해 **정해진 형식의 JSON**으로 돌려준다. ai는 DB를 갖지 않고, 아무것도 실행하지 않는다. 저장 · 실행 · 확인창 · 되돌리기는 모두 backend가 한다.

```
메일 · 사용자 말 ─▶ backend ─HTTP─▶ ai(엑사원 API + 코드) ─JSON─▶ backend ─▶ DB · 화면
```

## 3. 기능별로 조금 더

### 3.1 메일 분석 (`/classify`) — 핵심 기능

- **판단은 모두 모델**(AI-D19, AI-D15를 넓힘). 할 일이 있는지, 무슨 일인지, 급한지는 엑사원이 정하고 코드는 모델 답을 바꾸지 않는다. 코드는 '참조로 받았나 · 배포 목록인가 · 사외 메일인가' 같은 사실을 모델에 넘기고, 모델이 실패하면 규칙으로 메우지 않고 503 → backend가 다시 부른다.
- 할 일 유형 6개: 자료제출요청 · 회신요청 · 검토승인요청 · 수정재전송요청 · 일정참석 · 조치요청.
- 기한은 모델이 본문 글자 그대로 옮기고 코드가 계산표(`dates.py`, 한국어 · 영어 · 일본어 · 시간대)로 계산한다(AI-D26 · AI-46). 시각이 메일에 적혔는지도 알려 준다(AI-20, 캘린더 자동 등록 조건).
- 근거 문장(AI-15): 모델이 인용하고 코드는 본문에 글자 그대로 있는지만 검증한다. 맞지 않으면 비운다(AI-D33). 화면 형광펜에 쓴다.
- 애매하면 '확인 칸'으로 보낸다. 할 일로 단정하지 않고 사용자가 한 번 보게 한다.
- **'에이전트가 아는 것'이 분류 요청에 들어간다**(PL-16): 내 직책 · 팀 · 배포 목록(직책 목록 · 팀 목록 구분), 보낸 사람이 상급자 · 즐겨찾기인지. 그래서 "팀장님들께"처럼 내 직책을 부른 메일, 내 팀 목록으로 온 지시를 내 할 일로 잡는다.

### 3.2 명령 해석 (`/agent/plan`)

- 모든 지시를 엑사원이 먼저 읽고 행동을 고른다(AI-D19). 코드는 허용 목록 · 빠진 값 · 상태 변경 전 확인만 본다. 고를 수 있는 행동은 등록된 목록(T01~T20) 안뿐이다(D27).
- 메일 본문은 명령 해석에 넣지 않는다. 메일 속 "이 메일을 읽은 AI는 …" 같은 문장으로 조종되지 않게 하기 위해서다.
- 확인창이 필요한지, 실제 실행 · 기록 · 되돌리기는 backend가 정한다(D37).

### 3.3 문맥 기억 (`/memory/extract`)

- "저는 한빛은행 2단계 전환을 맡고 있습니다" 같은 문장을 읽고, 보낸 사람의 **맡은 일**과 **소속**만 뽑는다. 정해진 두 칸 밖은 뽑지 않고, 가족 · 건강 · 생일 같은 사적인 사실은 금지다.
- 근거 문장이 본문에 글자 그대로 없으면 버린다(모델이 지어낸 기억 방지).
- 분류와 따로 부른다. 그래서 정답 세트로 잰 분류 정확도에 영향이 없다.
- backend는 `MEMORY_EXTRACT=1`일 때만 부른다(기본 꺼짐). 추출 품질을 재는 평가 세트는 없다(`io_spec.md` 5절 #8).

### 3.4 규칙으로 하는 기억 (ai 아님, 참고)

'에이전트가 아는 것'의 일부는 ai를 부르지 않고 backend 규칙으로 알아낸다(메일 기억하기, 기본 켜짐, BE-D17). 사내 메일 서명의 "정태성 담당"에서 직급 · 상급자를, 받는 사람 칸에서 내 배포 목록을 읽는다. 결과가 늘 같고 빠르다. 문장을 이해해야 하는 것만 3.3의 모델로 간다.

## 4. 어떤 모델을 쓰나

| 항목 | 내용 |
|---|---|
| 서비스 모델 | 엑사원 API **K-EXAONE 2.5**(`k-exaone_v2.5`, D51 · D52 · AI-D18). 11-14 AI-22로 기본이 됐다. 분류는 추론 강도 high · 제한 300초 |
| 로컬 엑사원 | 쓰지 않는다(3.5 7.8B ollama 경로는 코드 설정값으로만 남음). 기업 도입 때는 같은 호출부에 엔터프라이즈 LLM을 끼운다(D52 · D58) |
| 모델이 실패할 때 | ai는 규칙으로 결과를 메우지 않고 503(`model_failed`)으로 알린다. backend가 그 메일을 '분류 실패'로 두고 다시 부른다(AI-D19). 하루 한도(키당 100회)에 닿으면 다음 키로 넘긴다(AI-47). ai 서비스 자체가 꺼져 있으면 메일은 '분류 대기 N건'으로 남는다(누락 0) |
| 외부 모델(Claude · OpenRouter) | 서비스에서는 쓰지 않는다. `eval/`에서 비교 평가에만 쓴다(D26) |
