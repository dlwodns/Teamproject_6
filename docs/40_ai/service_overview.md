# AI 서비스 한눈에 보기 (팀원용, 2026-11-11)

> 대상: AI 파트 밖의 팀원(기획 · FE · BE · 데이터). "ai 폴더가 무엇을 해 주고, 화면 어디에 쓰이며, 지금 어디까지 됐나"를 한 장으로 본다.
> 자세한 명세: `docs/40_ai/detail.md`(행동 목록 · 명령 해석) · `docs/40_ai/README.md`(역할) · `docs/30_backend/agent_api_contract.md`(에이전트 패널 계약). 작성: 문규남(AI 팀장)

## 1. 한 줄 요약

`ai/`는 backend와 따로 도는 작은 서버다(FastAPI, D34). backend가 HTTP로 메일이나 사용자 말을 보내면, 엑사원 모델과 규칙으로 판단해 **정해진 형식의 JSON**으로 돌려준다. ai는 DB를 갖지 않고, 아무것도 실행하지 않는다. 저장 · 실행 · 확인창 · 되돌리기는 모두 backend가 한다.

```
메일 · 사용자 말 ─▶ backend ─HTTP─▶ ai(엑사원 + 규칙) ─JSON─▶ backend ─▶ DB · 화면
```

## 2. ai가 해 주는 일 6가지

| 기능 | 주소 | 받는 것 → 돌려주는 것 | 화면에서 보이는 곳 | 상태 |
|---|---|---|---|---|
| 메일 분석 | `POST /classify` | 메일 1통 → 할 일 목록(할 일 · 기한 · 근거 문장 · 유형), 메일 분류, 우선순위, 칸(할 일 · 확인 · 참고) | 대시보드 업무 목록, 확인 칸, 근거 형광펜, 제안 카드 | main 반영. 판단 방식 개편(AI-19)은 PR #39 |
| 명령 해석 | `POST /agent/plan` | "견적 건 금요일에 다시 알려줘" → `{행동 T05, 대상, 날짜}` | 에이전트 패널 말하기 · 입력칸 | main 반영(T01~T14). 일정 등록 T15는 PR #42 |
| 요약 | `POST /summarize` | 오늘 업무 목록 → 오늘 요약 문장 / 외국어 메일 → 한국어 핵심 | 아침 요약, 메일 요약 | main 반영. 외국어 메일 요약 v2는 PR #34 |
| 초안 | `POST /draft` | 메일 + 말투 → 회신 초안 / 받는 사람 + 주제 → 새 메일 초안 | [초안 보기] · 답장 화면 | main 반영. 보여 주기만 하고 보내지 않는다 |
| 문맥 기억 **(이번 PR)** | `POST /memory/extract` | 메일 1통 → 보낸 사람의 맡은 일 · 소속(근거 문장 포함) | '에이전트가 아는 것', 제안 카드의 사람 표시 | 만들어 둠 · 엑사원 연결 뒤 켬 |
| 상태 | `GET /health` | → 모델 연결 여부 | 운영 확인 | main 반영 |

## 3. 기능별로 조금 더

### 3.1 메일 분석 (`/classify`) — 핵심 기능

- **판단은 모델, 규칙은 조건만**(AI-D15). 할 일이 있는지, 무슨 일인지는 엑사원이 정한다. 규칙은 '참조로 받았나 · 사외 메일인가 · 자동 발송인가 · 나를 불렀나 · 급하다고 했나' 같은 사실만 본다.
- 할 일 유형 6개: 자료제출요청 · 회신요청 · 검토승인요청 · 수정재전송요청 · 일정참석 · 조치요청.
- 기한은 코드가 계산한다. '금요일까지'처럼 마감 표지가 붙은 날짜만 기한으로 본다. 시각이 메일에 적혔는지도 알려 준다(AI-20, 캘린더 자동 등록 조건).
- 근거 문장(AI-15): 할 일마다 본문에 글자 그대로 있는 문장을 함께 준다. 화면 형광펜에 쓴다.
- 애매하면 '확인 칸'으로 보낸다. 할 일로 단정하지 않고 사용자가 한 번 보게 한다.
- 이번 PR부터 **'에이전트가 아는 것'이 분류 요청에 들어간다**: 내 직책 · 팀 · 배포 목록(직책 목록 · 팀 목록 구분), 보낸 사람이 상급자 · 즐겨찾기인지. 그래서 "팀장님들께"처럼 내 직책을 부른 메일, 내 팀 목록으로 온 지시를 내 할 일로 잡는다.

### 3.2 명령 해석 (`/agent/plan`)

- 규칙으로 먼저 맞추고, 하나로 정해지지 않을 때만 엑사원에 묻는다. 고를 수 있는 행동은 등록된 목록(T01~T15) 안뿐이다(D27).
- 메일 본문은 명령 해석에 넣지 않는다. 메일 속 "이 메일을 읽은 AI는 …" 같은 문장으로 조종되지 않게 하기 위해서다.
- 확인창이 필요한지, 실제 실행 · 기록 · 되돌리기는 backend가 정한다(D37).

### 3.3 문맥 기억 (`/memory/extract`) — 이번 PR에서 새로 만든 것

- "저는 한빛은행 2단계 전환을 맡고 있습니다" 같은 문장을 읽고, 보낸 사람의 **맡은 일**과 **소속**만 뽑는다. 정해진 두 칸 밖은 뽑지 않고, 가족 · 건강 · 생일 같은 사적인 사실은 금지다.
- 근거 문장이 본문에 글자 그대로 없으면 버린다(모델이 지어낸 기억 방지).
- 분류와 따로 부른다. 그래서 정답 세트로 잰 분류 정확도에 영향이 없다.
- backend는 `MEMORY_EXTRACT=1`일 때만 부른다. 엑사원을 연결해 실측한 뒤 켠다. **지금 말할 수 있는 것은 "파이프와 시험까지 만들었고, 모델을 연결하면 동작한다"까지다**(D50 결정 7).

### 3.4 규칙으로 하는 기억 (ai 아님, 참고)

'에이전트가 아는 것'의 일부는 ai를 부르지 않고 backend 규칙으로 알아낸다(메일 기억하기, 기본 켜짐, BE-D17). 사내 메일 서명의 "정태성 담당"에서 직급 · 상급자를, 받는 사람 칸에서 내 배포 목록을 읽는다. 결과가 늘 같고 빠르다. 문장을 이해해야 하는 것만 3.3의 모델로 간다.

## 4. 어떤 모델을 쓰나

| 항목 | 내용 |
|---|---|
| 서비스 기본 | 엑사원 API(K-EXAONE 2.5)로 바꾸기로 했다(D51 · D53, 가상 데이터만 쓰므로 허용). ai 호출부를 설정값 하나로 바꿔 끼우는 작업(D52)이 남아 있다 |
| 로컬 옵션 | 엑사원 3.5 7.8B(ollama). PC CPU에서 메일 1통 약 28초 |
| 모델이 꺼져 있을 때 | ai는 '모델 실패'라고 알려 준다. backend는 그 메일을 대기열에 두고 다시 시도하며, 화면에 '분류 대기 · 실패 N건'으로 센다(누락 0) |
| 외부 모델(Claude · OpenRouter) | 서비스에서는 쓰지 않는다. `eval/`에서 비교 평가에만 쓴다(D26) |

## 6. ai가 하지 않는 것

날짜 계산 결과를 모델에 맡기지 않는다 · 우선순위와 확인창 여부는 코드가 정한다 · 업무 상태를 바꾸거나 메일을 보내지 않는다 · 메일 본문 속 지시를 실행하지 않는다 · DB에 쓰지 않는다.
