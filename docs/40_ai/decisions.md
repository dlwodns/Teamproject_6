### AI-D9 · 개발 서버에서는 엑사원을 PC에서 돌리고, 서버는 터널로 부른다 (2026-11-02)

- 상태: 채택 · 제안: 문규남 · 결정: 문규남 · 리뷰: [미정] · 공동: — · 근거: AI-T4 · D41 · D44
- 결정: dev-server-02의 ai 서비스 · 평가는 PC(LG gram) ollama의 `EXAONE-3.5-7.8B-Instruct-GGUF:Q4_K_M`을 쓴다. 서버에는 엑사원 7.8B · llama-server를 띄우지 않는다.
- 결정: 연결은 PC → 서버 역방향 SSH 터널이고, 서버 쪽 출구는 TCP 포트가 아니라 내 홈의 0700 폴더 안 Unix 소켓(`~/run/exaone/ollama.sock`)이다. ollama는 PC의 127.0.0.1에만 연다.
- 결정: 실행은 `scripts/exaone-pc.sh run <명령>`으로 한다. 모델 digest · ollama 버전 고정값(`scripts/exaone-pc.env`)은 선택이다. 비어 있으면 경고만 내고, 채우면 다를 때 실행기가 멈추고 ai 서비스는 엑사원을 부르지 않는다. 11-03 기록값: digest `099a498b9cbf…` · ollama 0.34.0.
- 근거: 서버 user41 메모리 한도 5 GiB에 7.8B(4.5 GB)와 VS Code가 함께 올라가지 않는다. 2.4B는 서버에서 돌지만 벤치 v2에서 할 일 메일 1통을 놓쳤다(D15 위반). PC는 10/24 벤치 환경과 같아 평가 점수를 그대로 비교할 수 있다.
- 대안: 서버에서 2.4B 실행 — 정확도가 떨어져 기각. 서버 TCP 포트로 터널 — 같은 서버의 다른 계정이 붙을 수 있어 기각.
- D41(외부 LLM 경로 없음): PC도 팀이 관리하는 로컬 실행기이고 전송은 SSH로 암호화된다. 공통 결정에 반영할지는 팀 확인 `[결정 필요]`.
- 위험 · 남은 일: PC가 꺼지면 서비스는 규칙 결과만 낸다. 11/14 실배포 · IR Day 시연 때 모델 실행 위치(PC 상시 가동 또는 서버 메모리 한도 상향)는 미결 #6(detail 8절)에서 정한다 `[결정 필요]`.

### AI-D10 · 엑사원을 쓸 수 있으면 모든 메일을 엑사원에도 묻고, 규칙과 서로 보완해 합친다 (2026-11-05)

- 상태: 채택 · 제안: 문규남 · 결정: 문규남 · 리뷰: [미정] · 공동: — · 근거: D14 · D15 · plan 4.8절 · AI-T10
- 결정: `ROUTER_MODE=all`(기본). 규칙 결과는 늘 만들고, 엑사원 결과와 원칙대로 합친다. 엑사원이 꺼지면 규칙 결과만 낸다. `gate`(v3.2 문지기, 애매한 메일만 엑사원)는 비교 · 느린 장비용으로 남긴다.
- 합치기 원칙: 규칙만 찾은 할 일은 남긴다(D15). 엑사원이 더 낸 할 일이 나를 향하지 않은 문장('전 임직원은 ~')에서 나왔거나, 대상자 당부 공지 · '참고만 해 주세요' · 선택 요청('의견 있으신 분은') 메일에서 엑사원만 만든 할 일이면 확인 칸으로. 기한은 요청 문장에 붙은 규칙 기한을 먼저, 엑사원 기한은 마감 표지로 다시 확인. 유형은 요청 문장의 콕 집는 단서 > 메일 성격(kind) > 엑사원. 마지막에 유형과 할 일 여부를 맞춘다.
- 근거: 11/5 같은 엑사원 출력으로 비교했을 때 test에서 모든 메일 방식은 놓침 0, 문지기 방식은 1. 사용자 기준 '5~10분 늦어도 되지만 틀린 정보가 더 나쁘다'(11/5).
- 대안: 문지기 방식 유지 — 처음 보는 메일에서 누락이 남아 기각. 엑사원만 쓰기 — 공지 · 회신에 할 일을 만드는 버릇(AI-T5)이 그대로라 기각.
- 비용: PC CPU에서 메일 1통 약 28초(11/5 실측). 동기 요청으로 기다리지 않고 대기열로 처리한다. 동시 처리 · GPU 서빙은 미결 #6(detail 8절)에서 측정 후 정한다.

### AI-D11 · 기한은 마감 표지가 붙은 날짜만, 시각을 모르면 문구만, 최대한 빨리는 'ASAP' (2026-11-05)

- 상태: 채택 · 제안: 문규남 · 결정: 문규남(사용자 결정 11/5) · 리뷰: [미정] · 공동: 데이터 · 평가(라벨) · 근거: plan 4.8절 · `ai/app/pipeline/dates.py` `parse_deadline`
