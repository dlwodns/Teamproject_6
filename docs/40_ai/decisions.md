## 1. 결정

## AI-D9 · 개발 서버의 엑사원은 PC ollama에서 돌리고 역방향 SSH 터널로 부른다 (2026-11-02)

- 상태: 채택 · 제안: 문규남 · 결정: 문규남 · 리뷰: [미정] · 공동: — · 근거: AI-T4 · AI-D3 · D44
- 결정: dev-server-02의 ai 서비스 · 평가는 PC(LG gram)의 ollama에서 도는 `EXAONE-3.5-7.8B-Instruct-GGUF:Q4_K_M`을 쓴다. PC 127.0.0.1:11434 → `ssh -R` → 서버 `~/run/exaone/ollama.sock`(내 소유 0700 폴더)로 잇고, 서버에 TCP 포트를 열지 않는다. 실행은 `scripts/exaone-pc.sh run <명령>`. 모델 digest · ollama 버전 고정값은 선택이다(비어 있으면 경고만, 채우면 다를 때 멈춤).
- 근거: 서버 계정 메모리 한도(5 GiB, 스왑 없음)로는 7.8B를 올릴 수 없다(AI-T4). 2.4B는 벤치 v2에서 할 일 메일 1통을 놓쳤다(7.8B는 0통).
- 대안: 서버에서 2.4B 실행 — 정확도가 떨어져 기각. 서버 TCP 포트로 터널 — 같은 서버의 다른 계정이 붙을 수 있어 기각.
- 위험 · 남은 일: PC가 꺼지면 서비스는 규칙 결과만 낸다. 시연 · 배포 때 서빙 위치는 미결 #6(detail 8절)에서 정한다.

## AI-D10 · 평가 기준값을 PC 엑사원의 모델 digest · ollama 버전으로 고정한다 (2026-11-03)

- 상태: 채택 · 제안: 문규남 · 결정: 문규남 · 리뷰: [미정] · 공동: — · 근거: AI-D9 · eval/README 규칙
- 결정: `scripts/exaone-pc.env`에 `EXAONE_MODEL_DIGEST=099a498b9cbf…`(전체 값은 파일) · `OLLAMA_VERSION=0.34.0`을 적었다(`scripts/exaone-pc.sh pin`). 이 값과 다르면 실행기가 멈추고 ai 서비스는 규칙 결과만 낸다.
- 근거: 팀원 PC마다 모델 파일 · ollama 버전이 달라도 같은 태그로 보이므로, 고정값 없이는 채점 결과를 서로 비교할 수 없다. 11/3 실측(plan 4.2절)이 이 값 기준이다.
- 대안: 고정값을 비워 둔다 — 경고만 나고 다른 모델로 잰 수치가 섞일 수 있어 평가용으로는 쓰지 않는다.
- 위험 · 남은 일: ollama를 업데이트하거나 모델을 다시 받으면 값을 직접 고치고 평가를 다시 돌린다. 다른 팀원 PC는 같은 digest인지 `exaone-pc.sh check`로 먼저 확인한다.
