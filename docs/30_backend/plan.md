# 백엔드 구현계획

> 상태: 작업 18개 모두 닫힘 — 17개 완료 · BE-17 일부(레지스트리까지, MCP 서버는 아직)(11-27 코드 마감) · 작성: 문규남 · 결정: [파트 담당 확정 후] · 리뷰: [미정] · 갱신: 2026-11-27 (닫힌 이슈 #130 · #132~#135 · #141 · #142 결과로 상태 칸 · 담당 · 위험 최신화 / 11-07 홍태겸: v3.1 범위 반영, BE-10~BE-17 추가, #6 리뷰 반영)
> 목표일은 과정 일정 기준 제안이다(10/31 MVP 1차 · 11/7 에이전트 · 자동화 결합 E2E · 11/14 실배포 · 11/21 고도화 · 11/28 IR Day).

## 1. 목표

FastAPI(D38) + APScheduler + SQLite로 메일을 가져와 업무 단위로 저장하고, 대시보드 · 메일 · 설정 · 에이전트가 쓰는 API를 제공한다. 업무 상태를 사용자가 완료할 때까지 추적하고(D36 · D48) 리마인더를 보낸다(D35). 행동형 에이전트의 행동 레지스트리 · 확인 판정 · 실행을 맡는다(D37). 메일 연동 시 개인정보 처리(동의 · 암호화 · 최소 저장)를 맡는다.

## 2. 범위

| 이번 단계 (11/14 배포까지) | 이후 |
|---|---|
| dummy 연동, 업무 · 메일 · 설정 API, 상태 변경 · 되돌리기 · 일괄 완료(`action_log`), 행동 레지스트리 · preview/execute, 리마인더 스케줄러, 무응답 계산, 회신 감지 → 완료 확인, Outlook OAuth 연동(보낸편지함 포함), 개인정보 처리 | 캘린더 API(P1), 템플릿 전송 · MCP 서버(P2), IMAP 등 다른 메일 서비스, 자동 동기화 주기 조정 |

- P1 · P2는 P0 완료 전 착수하지 않는다(PL detail 12절). MCP 서버는 일정이 밀리면 뺀다. 지금은 레지스트리에 MCP 노출 이름 칸만 둔다(`detail.md` 5절).

- CI backend 단계가 건너뛰지 않고 통과한다(INF-9).
- 예: 완료 처리한 업무가 있는 상태에서 재동기화 → 상태 유지, 중복 저장 없음.
- 예: "공지 메일 다 처리했어"(대상 3건) → preview 반환 · 상태 변경 없음 → execute 후 3건 완료 · `action_log` 1건.

## 7. 위험

- 계정 연결: Microsoft Graph OAuth(인증 코드 + PKCE)로 정했다(BE-7). 회사 · 학교 계정은 그 조직 관리자 동의가 있어야 로그인된다(게시자 미확인 다중 테넌트 앱). 공개 배포는 브라우저마다 세션 사용자가 생기고 각자 자기 Outlook을 연결한다(D58, `AUTH_MODE=session`) — 계정 로그인이 아니라 쿠키라 쿠키를 지우면 새 사용자다.
- 사내 메일 연동 불가: 실제 성능은 더미 메일로만 확인한다. IR 발표 시연은 문규남 Outlook 계정에 더미 메일을 미리 보내 두고 그 계정을 연결해 한다(시연 DB 재적재 없음, 11-27).
- 엑사원 API 하루 호출 한도(키당 100회)를 공개 주소의 모든 사용자가 나눠 쓴다(`infra/railway_setup.md`).
- 테이블 변경: `create_all`만 쓰고 마이그레이션 도구가 없다(BE-D14 · BE-D25 · BE-D33). Alembic 도입은 `[미정]`.
- 스케줄러 중복 · 유실: 단일 프로세스 · 유일 제약 · 재시작 복구(PL detail 15절 R3). Railway에서도 backend 프로세스 1개다(`backend/README.md` 배포).
- 코드 마감(11-27) 뒤 남은 것: 웹 푸시 · 반복 일정 · MCP 서버 구축(BE-17, 레지스트리는 준비됨) · Graph 변경 알림 배포 주소 확인 `[미확인]`.
