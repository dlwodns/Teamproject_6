# AI 활용 기록 — 문규남

문규남(기획 · AI 팀장 · 인프라)이 이 프로젝트에서 AI 코딩 도구를 어떻게 썼는지 파트별로 정리합니다. 잘된 사례와 사람이 고친 사례를 함께 적고, 사례마다 레포에서 확인할 수 있는 근거(결정 번호 · PR · 커밋)를 붙였습니다. 다른 팀원의 작업은 넣지 않았습니다.

> 갱신: 2026-11-27 · 작성: 문규남(Claude Code로 결정 기록 · PR · 커밋을 대조해 초안을 잡고 직접 확인)

## 사용 도구와 규칙

**사용 도구** · 기획 · AI · 데이터 · 평가 · 백엔드 · 프론트엔드 · 인프라 — Claude Code

- AI 도움을 받은 PR은 본문 '작성 방식' 칸에 무엇을 맡겼는지 적었습니다(`work_rules.md` · PR 템플릿). 예: [#304](https://github.com/dlwodns/Teamproject_6/pull/304) "Claude로 원인을 CPython 소스에서 확인해 수정 초안을 잡았다".
- 서비스 경로(`frontend` · `backend` · `ai`)에서는 Claude를 부르지 않습니다. Claude · OpenRouter는 평가(`eval/`)에서만 쓰고, 커밋 전 훅과 CI의 `scripts/check_boundaries.py`가 이 경계를 막습니다(D26 · D53).
- 점수는 AI가 보지 않은 봉인 세트로만 판정합니다. 개발 세트 점수는 고친 방향이 맞는지 보는 데만 씁니다(AI-D15).

## 배운 것

- **AI는 눈앞의 오답을 하나씩 막는 쪽으로 간다.** 개발 세트 점수는 오르지만 처음 보는 메일에서 떨어졌다. 고칠 때마다 실패들의 공통 원인을 먼저 찾고, 봉인 세트로만 판정했다(AI-D15 · AI-D19 · AI-D30).
- **AI의 추론과 확인한 사실을 나눠 적는다.** 문서 · 소스로 확인한 것과 증상으로 추론한 것을 PR 본문에서 구분했다(#304).
- **AI가 만든 평가 데이터는 그 AI 쪽으로 치우칠 수 있다.** 작성자와 개발자를 나누고, SHA-256으로 고정한 봉인 세트를 한 번만 열었다(DE-D12 · `sealed_sets.md`).
