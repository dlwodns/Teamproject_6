## DE-T1 · MailEx 분류값을 정답으로 쓸 수 없음 (2026-10-24)

- 상태: 우회 · 발견: 문규남 · 해결: 문규남 · 리뷰: [미정] · 공동: — · 근거: log 10/24 · D24
- 증상: MailEx 3,936건의 `suggested_category`로 학습 · 평가하려 했다.
- 원인: `suggested_category`는 자동 추정값이다. 공지는 63건(1.6%)뿐이다.
- 해결: 정답 라벨은 우리 메일을 생성할 때 함께 지정하기로 했다(D24).
- 재발 방지: 자동 추정값을 정답으로 쓰지 않는다. 정답 라벨의 출처를 데이터 README에 적는다.

## DE-T2 · TF-IDF 분류기가 요청 메일을 놓침 (2026-10-24)

- 상태: 미해결 · 발견: 문규남 · 해결: [미정] · 리뷰: [미정] · 공동: — · 근거: log 10/24
- 증상: TF-IDF + 로지스틱 회귀(학습 800건)가 test 요청 192건 중 16건을 놓쳤다. 놓친 요청 0건을 만들려면 메일의 98%를 요청으로 표시해야 했다.
- 원인: 짧은 명령문, 긴 본문에 묻힌 요청, 질문형 요청, 의무 표현을 못 잡았다. 16건 중 6건은 정답 라벨 오류였다.
- 해결: 요청 표현 규칙을 앞에 붙여 test 16 → 6건, dev 21 → 7건으로 줄였다. 대신 요청이 아닌 메일을 요청으로 표시한 것이 약 25% 생겼다.
- 재발 방지: 규칙은 작성에 쓰지 않은 데이터(dev)로 따로 확인한다.

## DE-T3 · MailEx 원문에 실명 · 연락처가 많음 (2026-10-24)

- 상태: 해결 · 발견: 문규남 · 해결: 문규남 · 리뷰: [미정] · 공동: — · 근거: D24
- 증상: MailEx 원문에 발신자 실명 1,770명, 메일 주소 114건, 전화번호 형식 229건이 있었다.
- 원인: Enron 실제 메일이 원본이다. 라이선스는 확인하지 못했다 `[미확인]`.
- 해결: 원문은 `data/raw/`에만 두고 레포에서 제외했다. 상황만 추출해 가상 인물로 새로 쓴다.
- 재발 방지: `.gitignore`로 `data/raw/`를 막는다. PR 체크 항목에 실명 데이터 확인을 둔다.
