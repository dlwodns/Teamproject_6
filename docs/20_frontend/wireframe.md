## 2. S1 메인 · 데스크톱 3단 (폭 1200px 이상)

> **1차 검토 결과 (2026-10-10):** L 승인 · M2 승인 · R 구조 승인. "요소가 너무 많다"는 의견에 따라 M1 · M3 · R을 줄였습니다. 줄인 근거는 2-4절 레퍼런스 조사.

```
┌─────────────────────────┬────────────────────────────────────────────┬──────────────────────────────────────┐
│ L0 ☰  미처리 메일       │ M1 [미처리 23]  완료   전체        15:40 ⟳ │ R1 견적서 회신 요청                  │
│                         │ M1-c (전체) 회신 요청 검토 공지 기타       │   김OO · 10/08 09:12 · 계정A [요청▾] │
│ L1 ▾ 즐겨찾기           │ M2 [정렬: 최신순 ▾]  [묶기: 없음 ▾]        │ R2 [✓ 처리 완료]  나중에   ⊘   ★   ↗ │
│    ▣ 모든 미처리     23 ├────────────────────────────────────────────┤──────────────────────────────────────┤
│    ★ 중요 보관함      3 │ M3 [요청] ☐ 김OO    견적서 회신 요청   2일 │ R3 본문 미리보기                     │
│    ● 김OO (대상자)    4 │    [회신] ☐ 박OO    일정 확인 부탁     3일 │    (본문 읽기 꺼짐이면 R4 안내)      │
│    ● 박OO (대상자)    2 │    [검토] ☐ 이OO ★  계약서 검토 건     4일 │                                      │
│    + 대상자 추가        │    [공지] ☐ 인사팀  10월 교육 안내     5일 │                                      │
│ L2 ▾ account-a@…        │    …                                       │                                      │
│    미처리            15 │                                            │                                      │
│      · 회신           5 │                                            │                                      │
│      · 요청           4 │                                            │                                      │
│      · 검토           3 │                                            │                                      │
│      · 공지           2 │                                            │                                      │
│      · 기타           1 │                                            │                                      │
│    완료                 │                                            │                                      │
│    제외                 │ M6 ┌──────────────────────────┐            │                                      │
│    전체                 │    │ 처리됨 · [되돌리기]   ✕  │ (토스트)   │                                      │
│ L3 ▸ account-b@…     8  │    └──────────────────────────┘            │                                      │
│ L4 + 계정 추가          │                                            │ R5 [보류] 분류 근거 보기 ▸           │
│ L6 ⚙ 설정               │                                            │    (만들 경우 · 작은 글씨 · 접힘)    │
└─────────────────────────┴────────────────────────────────────────────┴──────────────────────────────────────┘
   폭 260px (접으면 48px)              가변 (최소 360px)                          가변 (최소 400px)
```

- `M1`: `[미처리 23]`은 선택된 탭(굵게 + 아래 밑줄). 오른쪽 위 구석의 `15:40 ⟳`가 `M1-r`(작은 회색 글씨 + 아이콘만 있는 버튼).
- `M1-c`: `(전체)`가 선택된 상태. 하나만 고르는 토글 버튼 줄.
- `M3`: `★`는 켜진 메일에만 보입니다(이OO 줄). 꺼진 ☆는 마우스를 올릴 때만 보입니다.
- `R2`: 채운 버튼은 `✓ 처리 완료` 하나. 나머지는 테두리 없는 버튼 · 아이콘(마우스를 올리면 이름 툴팁).

### 2-1. 왼쪽 · 분류 창 (L)

| `L2` | ▾ 계정 이메일 | 토글 | 계정 하위 목록 접기 · 펴기. 접힌 상태에서는 미처리 건수만 표시(`L3`처럼) | 주소가 길면 말줄임(…) + 마우스를 올리면 전체 주소 툴팁 |
| `L2-a` | 미처리 · 업무별 하위 | 메뉴 | `미처리` = 그 계정의 미처리 전체. 하위 `회신 · 요청 · 검토 · 공지 · 기타` = 업무 분류로 걸러 봄 | 0건인 업무는 흐리게 표시(숨기지 않음 — 위치가 바뀌지 않게) |

**왼쪽 창 규칙**
- 펼침 · 접힘 상태와 마지막으로 고른 메뉴는 다음 접속 때 그대로 복원합니다.
- 선택된 메뉴는 Outlook처럼 회색 배경 + 굵은 글씨(캡처 1의 `받은 편지함`)로 표시합니다.

| `M3` 마우스 올림 | ✓ · ⊘ · ☆ | 버튼 | 줄 끝 날짜 자리에 빠른 동작 버튼이 나타남 (Outlook 목록 동작과 같은 방식) | 터치 화면은 마우스 올림이 없으므로 줄을 왼쪽으로 밀면 같은 버튼 `[가설]` |

**구조(R0~R4)는 v1 그대로 승인.** 1차 검토에서 "보이는 것은 더 심플하게"를 반영해 아래처럼 줄였습니다(근거 2-4절).

| 줄인 것 | v1 | v1.1 |

| 발신자 줄 | 이름 + `<이메일 주소>` + `[☆]` 두 줄 | 이름 · 받은 시각 · 계정을 **한 줄**로. 이메일 주소는 이름에 마우스를 올릴 때 툴팁 |

### 2-4. 레퍼런스 조사 (M · R 단순화 근거, 2026-10-10)

| 레퍼런스 | 확인한 것 | 이 문서에 반영 |
|---|---|---|
| Outlook 집중된 받은 편지함 [R9] | 받은 편지함 목록 **맨 위에 `집중` · `기타` 탭 두 개**를 두고 언제든 전환. 탭 외의 제목 줄이 따로 없음 | `M1`을 제목 + 건수 대신 상태 탭 `미처리 · 완료 · 전체`로 교체 |

**정리한 원칙 (M · R 공통)**
1. 한 영역에 **눈에 띄는 동작은 하나**: 목록은 ☐ 체크, 미리보기는 `✓ 처리 완료`. 나머지는 아이콘 · 글자 버튼으로 무게를 낮춤.
2. 이미 다른 곳에 보이는 정보는 반복하지 않음: 범위(왼쪽 선택), 이메일 주소(툴팁), 판별 근거(보류).
3. 보조 정보(동기화 시각 · 계정)는 작은 회색 글씨로 구석에.

### 3-2. 업무 분류 규칙 초안 `[가설]` — 규칙 기반 `[결정]`, AI 없음

위에서부터 처음 맞는 규칙 하나로 정합니다. 키워드는 제목 기준, `본문 읽기` 켜짐이면 본문 첫 부분도 봅니다.

| 순서 | 업무 | 규칙 예 | 미처리 목록에 넣는가 |
|---|---|---|---|
| 1 | 검토 | "검토", "확인 부탁", "리뷰", "결재", 첨부 파일 + "확인" | 넣음 |
| 2 | 요청 | "요청", "부탁드립니다", "제출", "회신 기한", "~까지" | 넣음 |
| 3 | 회신 | 본인이 받는 사람(To)에 직접 있음 + 물음표(?) 또는 "회신", "답변", "의견" | 넣음 |
| 4 | 공지 | "[공지]", "안내", "공유드립니다", 받는 사람이 많음(예: 10명 이상), 본인이 참조(CC)만 | **인터뷰로 결정** (읽기만 하면 끝인지) |
| 5 | 기타 | 위에 해당 없음 | 넣음 |

- 사용자가 `R1`에서 고치면 그 메일은 규칙보다 사용자 값을 따릅니다. 같은 발신자의 다음 메일까지 따라 바꿀지는 `[미정]`.
- 키워드 · 기준 수치(10명 등)는 인터뷰 후 `architecture.md` 8절에 확정합니다.

### 6-2. 토큰 (Fluent 2 값)

```css
:root {
  --dur-faster: 100ms;  /* durationFaster  : 체크·★·마우스 올림 */
  --dur-fast:   150ms;  /* durationFast    : 접힘·퇴장·내용 교체 */
  --dur-normal: 200ms;  /* durationNormal  : 펼침·토스트·줄 접힘 */
  --dur-gentle: 250ms;  /* durationGentle  : 서랍 열림 */
  --dur-slow:   300ms;  /* durationSlow    : 휴대폰 미리보기 진입 */
  --ease-decel: cubic-bezier(0,0,0,1);        /* curveDecelerateMid : 들어올 때·펼칠 때 */
  --ease-decel-max: cubic-bezier(0.1,0.9,0.2,1); /* curveDecelerateMax : 서랍·전체 화면 진입 */
  --ease-accel: cubic-bezier(0.8,0,0.78,1);   /* curveAccelerateMin : 나갈 때·접을 때 */
  --ease-easy:  cubic-bezier(0.33,0,0.67,1);  /* curveEasyEase      : 제자리 변화(색·회전) */
}
```

### 6-4. 구현 규칙

1. **토글은 `<details>`가 아니라 `<button aria-expanded>`로 만듭니다.** `<details>`는 열고 닫는 전환을 애니메이션할 기본 방법이 없습니다 [R8]. 버튼에 `aria-expanded`(펼침 true/접힘 false)와 `aria-controls`를 달고 Enter · Space로 토글합니다 [R6].
2. **높이 애니메이션은 그리드 행 방식**으로 합니다. 내용 높이(`auto`)로의 애니메이션을 허용하는 `interpolate-size: allow-keywords`는 아직 일부 주요 브라우저에서 동작하지 않으므로 [R8] 보조 수단으로만 씁니다.

```css
.toggle-body { display: grid; grid-template-rows: 0fr;
  transition: grid-template-rows var(--dur-fast) var(--ease-accel); }
.toggle-body[data-open="true"] { grid-template-rows: 1fr;
  transition: grid-template-rows var(--dur-normal) var(--ease-decel); }
.toggle-body > .inner { overflow: hidden; }
.chevron { transition: transform var(--dur-normal) var(--ease-easy); }
[aria-expanded="true"] .chevron { transform: rotate(90deg); }

@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after { transition-duration: 0ms !important;
    animation-duration: 0ms !important; animation-iteration-count: 1 !important; }
}
```
   `fr` 값의 전환 지원은 구현 시 대상 브라우저(Chrome · Edge · Safari iOS)에서 직접 확인합니다 `[불확실]`.
3. **키프레임 대신 transition**을 씁니다. 펼치는 도중에 다시 누르면 transition은 현재 위치에서 자연스럽게 되돌아가지만, 키프레임 애니메이션은 처음부터 다시 시작해 튑니다.
4. **처음 열 때는 움직이지 않습니다.** 접속 시 지난 펼침 상태를 복원할 때는 애니메이션 없이 바로 그린 뒤, 사용자 조작부터 애니메이션을 켭니다 `[제안]`.
5. **동작 줄이기 = 이동 제거 + 짧은 페이드만.** 기기 설정(`prefers-reduced-motion: reduce`) [R5] 또는 `P5`가 켜지면 슬라이드 · 회전 · 크기 변화는 0ms로, 상태 변화는 100ms 이하 페이드로만 표시합니다(상호작용으로 생기는 불필요한 움직임은 끌 수 있어야 함 [R7]). 동기화 회전 아이콘은 "동기화 중…" 글자로 바꿉니다.
6. 왼쪽 트리 키보드: ↑↓ 이동, → 접힌 항목 펼치기 / 펼친 항목은 첫 하위로, ← 펼친 항목 접기 / 하위 항목은 상위로 [R6].

### 11-2. 동작 규칙

| 상황 | 동작 | 구분 |
|---|---|---|
| 한 업무가 여러 칸 조건에 맞음 | 맞는 칸 모두에 표시. `D1` 총계는 1건 | `[결정]` D18-4 |

| 칸을 보는 중 새 업무 도착(SSE) | 보이는 카드를 밀지 않는다. 칸 머리에 `+N 새 항목` → 누르면 맨 위에 넣고 2초 강조. 칸이 비어 있으면 바로 넣는다 | `[제안]` (web.dev CLS) |
| ⏰ 나중에 | 메뉴: 오늘 오후 · 내일 오전 · 다음 주 월요일 · 날짜 선택. 칸에서 빠지고 `D1 미룸`에 남는다. 시각이 되면 원래 칸으로 돌아와 `+N 새 항목` | `[제안]` |

**채택한 점**
- 메뉴 위치 왼쪽 + 버튼 하나로 접고 펴기: Gmail(Show/Hide main menu) · Notion(`<<`) · Outlook(navigation pane 표시/숨김)이 모두 버튼으로 메뉴를 숨긴다. 우리 메뉴는 3개라 접어도 아이콘만으로 구분된다.
- 보조 도구는 오른쪽 패널: Gmail이 Keep · Tasks를 오른쪽 side panel로 연다 → 에이전트를 오른쪽 패널로 연다(FE-D13). 진입은 리뷰 요청대로 오른쪽 아래 원형 버튼.
