## 2. S1 메인 · 데스크톱 3단 (폭 1200px 이상)

> **1차 검토 결과 (2026-10-10):** L 승인 · M2 승인 · R 구조 승인. "요소가 너무 많다"는 의견에 따라 M1 · M3 · R을 줄였습니다. 줄인 근거는 2-4절 레퍼런스 조사.

```
┌─────────────────────────┬────────────────────────────────────────────┬──────────────────────────────────────┐
│ L0 ☰  미처리 메일       │ M1 [미처리 23]  완료   전체        15:40 ⟳ │ R1 견적서 회신 요청                  │
│                         │ M1-c (전체) 회신 요청 검토 공지 기타       │   김OO · 10/08 09:12 · 계정A [요청▾] │
│ L1 ▾ 즐겨찾기           │ M2 [정렬: 최신순 ▾]  [묶기: 없음 ▾]        │ R2 [✓ 처리 완료]  나중에   ⊘   ★   ↗ │
│    ▣ 모든 미처리     23 ├────────────────────────────────────────────┤──────────────────────────────────────┤
│    ★ 중요 보관함      3 │ M3 [요청] ☐ 김OO    견적서 회신 요청   2일 │ R3 본문 미리보기                     │
│    ● 김OO (대상자)    4 │    [회신] ☐ 박OO    일정 확인 부탁     3일 │    (본문 읽기 꺼짐이면 R4 안내)      │
│    ● 박OO (대상자)    2 │    [검토] ☐ 이OO ★  계약서 검토 건     4일 │                                      │
│    + 대상자 추가        │    [공지] ☐ 인사팀  10월 교육 안내     5일 │                                      │
│ L2 ▾ account-a@…        │    …                                       │                                      │
│    미처리            15 │                                            │                                      │
│      · 회신           5 │                                            │                                      │
│      · 요청           4 │                                            │                                      │
│      · 검토           3 │                                            │                                      │
│      · 공지           2 │                                            │                                      │
│      · 기타           1 │                                            │                                      │
│    완료                 │                                            │                                      │
│    제외                 │ M6 ┌──────────────────────────┐            │                                      │
│    전체                 │    │ 처리됨 · [되돌리기]   ✕  │ (토스트)   │                                      │
│ L3 ▸ account-b@…     8  │    └──────────────────────────┘            │                                      │
│ L4 + 계정 추가          │                                            │ R5 [보류] 분류 근거 보기 ▸           │
│ L6 ⚙ 설정               │                                            │    (만들 경우 · 작은 글씨 · 접힘)    │
└─────────────────────────┴────────────────────────────────────────────┴──────────────────────────────────────┘
   폭 260px (접으면 48px)              가변 (최소 360px)                          가변 (최소 400px)
```

- `M1`: `[미처리 23]`은 선택된 탭(굵게 + 아래 밑줄). 오른쪽 위 구석의 `15:40 ⟳`가 `M1-r`(작은 회색 글씨 + 아이콘만 있는 버튼).
- `M1-c`: `(전체)`가 선택된 상태. 하나만 고르는 토글 버튼 줄.
- `M3`: `★`는 켜진 메일에만 보입니다(이OO 줄). 꺼진 ☆는 마우스를 올릴 때만 보입니다.
- `R2`: 채운 버튼은 `✓ 처리 완료` 하나. 나머지는 테두리 없는 버튼 · 아이콘(마우스를 올리면 이름 툴팁).

### 2-1. 왼쪽 · 분류 창 (L)

- 펼침 · 접힘 상태와 마지막으로 고른 메뉴는 다음 접속 때 그대로 복원합니다.

**정리한 원칙 (M · R 공통)**
1. 한 영역에 **눈에 띄는 동작은 하나**: 목록은 ☐ 체크, 미리보기는 `✓ 처리 완료`. 나머지는 아이콘 · 글자 버튼으로 무게를 낮춤.
2. 이미 다른 곳에 보이는 정보는 반복하지 않음: 범위(왼쪽 선택), 이메일 주소(툴팁), 판별 근거(보류).
3. 보조 정보(동기화 시각 · 계정)는 작은 회색 글씨로 구석에.

### 3-2. 업무 분류 규칙 초안 `[가설]` — 규칙 기반 `[결정]`, AI 없음

위에서부터 처음 맞는 규칙 하나로 정합니다. 키워드는 제목 기준, `본문 읽기` 켜짐이면 본문 첫 부분도 봅니다.

| 순서 | 업무 | 규칙 예 | 미처리 목록에 넣는가 |
|---|---|---|---|
| 1 | 검토 | "검토", "확인 부탁", "리뷰", "결재", 첨부 파일 + "확인" | 넣음 |
| 2 | 요청 | "요청", "부탁드립니다", "제출", "회신 기한", "~까지" | 넣음 |
| 3 | 회신 | 본인이 받는 사람(To)에 직접 있음 + 물음표(?) 또는 "회신", "답변", "의견" | 넣음 |
| 4 | 공지 | "[공지]", "안내", "공유드립니다", 받는 사람이 많음(예: 10명 이상), 본인이 참조(CC)만 | **인터뷰로 결정** (읽기만 하면 끝인지) |

### 6-2. 토큰 (Fluent 2 값)

```css
:root {
  --dur-faster: 100ms;  /* durationFaster  : 체크·★·마우스 올림 */
  --dur-fast:   150ms;  /* durationFast    : 접힘·퇴장·내용 교체 */
  --dur-normal: 200ms;  /* durationNormal  : 펼침·토스트·줄 접힘 */
  --dur-gentle: 250ms;  /* durationGentle  : 서랍 열림 */
  --dur-slow:   300ms;  /* durationSlow    : 휴대폰 미리보기 진입 */
  --ease-decel: cubic-bezier(0,0,0,1);        /* curveDecelerateMid : 들어올 때·펼칠 때 */
  --ease-decel-max: cubic-bezier(0.1,0.9,0.2,1); /* curveDecelerateMax : 서랍·전체 화면 진입 */
  --ease-accel: cubic-bezier(0.8,0,0.78,1);   /* curveAccelerateMin : 나갈 때·접을 때 */
  --ease-easy:  cubic-bezier(0.33,0,0.67,1);  /* curveEasyEase      : 제자리 변화(색·회전) */
}
```

### 6-4. 구현 규칙

1. **토글은 `<details>`가 아니라 `<button aria-expanded>`로 만듭니다.** `<details>`는 열고 닫는 전환을 애니메이션할 기본 방법이 없습니다 [R8]. 버튼에 `aria-expanded`(펼침 true/접힘 false)와 `aria-controls`를 달고 Enter · Space로 토글합니다 [R6].
2. **높이 애니메이션은 그리드 행 방식**으로 합니다. 내용 높이(`auto`)로의 애니메이션을 허용하는 `interpolate-size: allow-keywords`는 아직 일부 주요 브라우저에서 동작하지 않으므로 [R8] 보조 수단으로만 씁니다.

```css
.toggle-body { display: grid; grid-template-rows: 0fr;
  transition: grid-template-rows var(--dur-fast) var(--ease-accel); }
.toggle-body[data-open="true"] { grid-template-rows: 1fr;
  transition: grid-template-rows var(--dur-normal) var(--ease-decel); }
.toggle-body > .inner { overflow: hidden; }
.chevron { transition: transform var(--dur-normal) var(--ease-easy); }
[aria-expanded="true"] .chevron { transform: rotate(90deg); }

@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after { transition-duration: 0ms !important;
    animation-duration: 0ms !important; animation-iteration-count: 1 !important; }
}
```
   `fr` 값의 전환 지원은 구현 시 대상 브라우저(Chrome · Edge · Safari iOS)에서 직접 확인합니다 `[불확실]`.
3. **키프레임 대신 transition**을 씁니다. 펼치는 도중에 다시 누르면 transition은 현재 위치에서 자연스럽게 되돌아가지만, 키프레임 애니메이션은 처음부터 다시 시작해 튑니다.
4. **처음 열 때는 움직이지 않습니다.** 접속 시 지난 펼침 상태를 복원할 때는 애니메이션 없이 바로 그린 뒤, 사용자 조작부터 애니메이션을 켭니다 `[제안]`.
5. **동작 줄이기 = 이동 제거 + 짧은 페이드만.** 기기 설정(`prefers-reduced-motion: reduce`) [R5] 또는 `P5`가 켜지면 슬라이드 · 회전 · 크기 변화는 0ms로, 상태 변화는 100ms 이하 페이드로만 표시합니다(상호작용으로 생기는 불필요한 움직임은 끌 수 있어야 함 [R7]). 동기화 회전 아이콘은 "동기화 중…" 글자로 바꿉니다.
6. 왼쪽 트리 키보드: ↑↓ 이동, → 접힌 항목 펼치기 / 펼친 항목은 첫 하위로, ← 펼친 항목 접기 / 하위 항목은 상위로 [R6].

- 조건을 하나도 고르지 않으면 `[저장]`을 끄고 "조건을 1개 이상 고르세요"를 띄운다(Copilot Prioritize: 기준 1개 이상 필수).

### 13-3. 동작 규칙

| 상황 | 동작 |
|---|---|
| 업무 ☐ 체크 | 체크 상자가 채워짐(150ms) → 그 업무의 모든 줄(긴급 · 유형에 중복된 줄 포함)이 오른쪽으로 빠지며 사라짐(250ms) → 높이 접힘(200ms) → N1 · 칸 건수 갱신 → 되돌리기 토스트(8초, 마우스를 올리거나 포커스가 있으면 멈춤) |
| 되돌리기 | 상태 · 숫자 원래대로, 토스트 '되돌렸어요' |
| N1 기간 바꾸기 | 숫자만 바뀌고 2열 칸은 그대로(2열은 항상 '지금 남은 업무') |
| 업무 줄 · 확인사항 줄 · 리마인더 [메일 보기] | 메일 화면으로 넘어가 그 메일을 고른다. 지금 메일함에 없는 메일이면 받은편지함으로 바꾼다. 새 업무 점 · 굵은 글씨가 사라진다 |
| 더보기 · `+N건 더보기` | 오른쪽 사이드바(LP)에 그 칸 전부. 사이드바 안 줄을 눌러도 메일로 이동 |
| 화면 오가기 | 메일 화면 위 [← 대시보드] 버튼 또는 **Alt+←**로 이전 화면, **Alt+→**로 다시 앞으로. 입력칸 안에서는 동작하지 않는다(Mac 단어 이동과 겹침). 실제 앱은 라우터 history로 만들어 브라우저 뒤로 · 앞으로 · 마우스 뒤로 버튼과 같게 한다 |
| 패널 | 더보기 사이드바 · 에이전트 중 하나만 열린다. Esc 또는 ✕로 닫는다 |
| ✦ 에이전트 | 버튼이 패널로 자라며 열린다(컨테이너 변형 350ms, View Transitions 미지원이면 미끄러져 열림) |
| 동작 줄이기 | 기기 설정이 켜져 있으면 이동 · 변형 애니메이션 0ms, 상태 바뀜만 즉시 보인다 |

```
│ │ ☑ 협력사 평가표 작성  ☑ 미팅 참석 회신 │ │
│ │                 [취소] [3건 완료 처리] │ │
│ └───────────────────────────────────────┘│
│ ┌ 3건을 완료로 바꿨어요 ─────────────┐   │  ← 결과 카드(과거형) + 실행 취소
│ │ ✓ … ✓ … ✓ …  ▸어떻게 해석했나요     │   │
│ │                        [실행 취소] │   │
├────────────────────────────────────┤
│ 선택한 메일 계약서 수정본…  [빼기]   │  ← "이거 완료"용 선택 메일 id(메일 화면에서 고른 메일)
│ [ 입력칸                ] 🎤 [보내기] │
└────────────────────────────────────┘
```

| 요소 | 규칙 | 근거 |
|---|---|---|
| 단계 | 명령 이해 → 대상 찾기 → (확인) → 실행. 조회 · 표시(T01 · T06 · T07)와 상태 변경 1건(T04 · T05)은 확인 단계를 두지 않는다. 각 단계 상태: 대기 ○ · 진행 ◌ · 완료 ✓ · 확인 대기 ? · 실패 ! · 건너뜀 | D37 · 벤치마크 Task · ChainOfThought |
| 진행 중 한 줄 | "지금 하는 일…(진행형) · 단계 n/전체 · 경과 초(3초부터)" + [중지]. 눌러서 단계 목록 펼침 | Fluent Wait UX · NN/g |
| 엑사원 경로 | 규칙에 안 걸려 엑사원이 해석할 때, 3초가 넘으면 "엑사원이 명령을 해석하는 중… (최대 30초)". 남은 시간은 추정하지 않는다 | AI-D9 · Fluent |
| 끝나면 | 단계 줄이 "N단계 완료 · M초"로 접힌다. 실패하면 펼친 채로 멈춘다 | 벤치마크 공통 |
| 확인 카드 | 대화 흐름 안에 둔다(모달 아님). 동사로 쓴 질문 제목 + 대상 목록(체크를 풀어 뺄 수 있음) + 동사 버튼 [N건 완료 처리] [취소]. 미리 선택된 버튼 없음, 카드가 뜨면 포커스를 카드로 | D37 · NN/g 확인 대화상자 |
| 결과 카드 | 과거형 제목 + 대상 목록 + [실행 취소](카드에 계속 남음, 누르면 '되돌렸어요') + '어떻게 해석했나요'(접힘: "'김 팀장님'을 김민준 팀장으로") | D37 · T04 연결 |
| 회신 초안(T07) | 초안 미리보기 + [답장 화면에서 열기] → 메일 화면의 답장 작성으로 | D37 |
| 발송(T14, P1) | 받는 사람 · 제목 · 본문 미리보기(고칠 수 있음) + "보낸 뒤에는 되돌릴 수 없어요" + [메일 보내기] [취소] | D37 |
| 지원하지 않는 요청 | 명령 이해 단계 실패 + "지원하지 않는 요청이에요" + 이렇게 말해 보라는 예시 명령 3개(눌러서 실행) | D27 |
| 중지 | 진행 중 언제든. "중지했어요. 바뀐 것은 없어요" | NN/g · Linear |
| 음성 🎤 | 누르면 '듣는 중'(빨간 바탕 + 깜빡임, 동작 줄이기면 깜빡임 없음) → 글자가 입력칸에 들어가고 사용자가 보내기를 누른다. 지원하지 않는 브라우저면 버튼을 숨긴다 | D29 · FE-8 |
| 화면 읽기 | 패널에 `role="status"` 영역 하나를 처음부터 두고, 단계가 바뀔 때만 문구를 바꾼다(토큰 스트림을 읽히지 않음) | 접근성 조사 |

### 13-5. 답장 · 템플릿 · 완료 확인 시트

**답장 작성 (메일 화면 오른쪽, v3.2 Outlook 구성 · UX-D14):** [답장]을 누르면 메일 자리가 작성 화면으로 바뀐다. 위에서 아래 순서는 Outlook 새 메일 쓰기와 같고, 본문 칸만 UX-D5(하고 싶은 말 + 템플릿)다.

```
┌ 답장 ─────────────────────────────────────────────────────────┐
│ [보내기]  보낸 사람: 사내 메일 ▾                         [삭제] │
│ [받는 사람]  김민준 팀장 <주소>          (답장에선 고정)         │
│ [참조]  ·  숨은 참조                      (P1)                  │
│ 제목  RE: 계약서 수정본 검토 및 협력사 평가                     │
│ ─────────────────────────────────────────────────────────── │
│ 템플릿 [기본 회신 ▾]                       [엑사원으로 다듬기]  │
│ ┌ 내용(하고 싶은 말만) ───────────────────────────────────┐   │
│ │ 수정본 검토했고 오늘 중으로 승인 올리겠습니다.            │   │
│ └────────────────────────────────────────────────────────┘   │
│ 미리보기: 김민준 팀장님, 안녕하세요. ‹쓴 내용 밑줄› … 이준호 드림 │
└───────────────────────────────────────────────────────────────┘
```

| 요소 | 내용 | 범위 `[제안]` |
|---|---|---|
| [보내기] | 맨 위 왼쪽 주 버튼. 사용자가 눌러야만 보낸다(D48). 버튼이 그 자리에서 '보내는 중(스피너)' → '보냄 ✓'로 바뀐다(폭 유지). Outlook의 [보내기 ▾](예약 보내기)는 P1 | P0 · ▾ P1 |
| 보낸 사람 ▾ | 연결된 계정(사내 메일 · Outlook) 중 고름. 기본은 원메일을 받은 계정 | P0 |
| [받는 사람] | 원메일 발신자. 답장에서는 고칠 수 없다 | P0 |
| [참조] · 숨은 참조 | Outlook처럼 버튼을 누르면 주소 고르기. 숨은 참조는 글자 링크로 접어 둠. 전체 회신 · 전달과 함께 | P1 |
| 제목 | `RE: {원메일제목}` 자동(이미 RE:면 그대로) | P0 |
| 템플릿 | 기본 회신 · 자료 송부 · 일정 회신 · 확인했습니다 (설정 › 템플릿에서 관리, P1) | P0 |
| 내용 | **하고 싶은 말만** 쓴다. 예: "수정본 검토했고 오늘 중으로 승인 올리겠습니다." 서식 막대(굵게 · 목록 · 글꼴 등)는 두지 않는다 — 템플릿이 형식을 맡는다 | P0 |
| 미리보기 | 템플릿의 인사 · 맺음 · 서명 사이에 쓴 내용을 넣어 보여 준다. 쓴 부분은 밑줄로 구분. 템플릿을 바꿔도 쓴 내용은 그대로 | P0 |
| 엑사원으로 다듬기 | 선택. `/draft`로 문장을 다듬은 초안을 보여 준다(보내지 않음). 연결 전에는 비활성 | P0(비활성) |
| [삭제] | 오른쪽 위. 쓰던 답장을 버리고 메일 보기로 돌아감. 내용이 있으면 '버릴까요? 예 / 아니오' | P0 |
| 새 창으로 열기 · 첨부 | Outlook 오른쪽 위 팝아웃 · 삽입 › 첨부 | P1 |
| 뺌 | 반응(이모지) · 앱 · 민감도 · 중요도 · 서식 막대 · 그리기 | — |

템플릿 자리표시자는 `{수신자명}` · `{원메일제목}`에 **`{내용}`(사용자가 쓴 말) · `{발신자명}`** 을 더한다 → `templates` 테이블 규칙과 BE 확인 필요.

**완료 확인 아래 시트 `BS`:** 보내기가 끝나면 같은 메일에 남은 업무가 있을 때만 뜬다. 없으면 토스트 '답장을 보냈어요'만.

```
            ┌──────────────────────────────────────────┐
            │ 완료로 처리할까요?                          │
            │ ┌──────────────────────────────────────┐ │
            │ │ ☑ 계약서 수정본 검토 · 승인  [오늘 18:00] │ │
            │ │ ☑ 협력사 평가표 작성         [11/9(월)]  │ │
            │ └──────────────────────────────────────┘ │
            │ ☐ 오늘 다시 보지 않음                      │
            │                          [아니오]  [ 예 ]  │
            └──────────────────────────────────────────┘
```

| 항목 | 규칙 |
|---|---|
| 문구 | 제목 **"완료로 처리할까요?"**, 버튼 **예 / 아니오**, 체크박스 **"오늘 다시 보지 않음"**. 다른 설명 문구는 두지 않는다 (UX-D5 · UX-D11) |
| 업무 목록 | 그 메일의 미처리 업무 전부, 기본 체크. 체크를 풀면 그 업무는 남긴다 |
| 예 | 체크한 업무 완료 → 토스트 'N건을 완료로 바꿨어요 [되돌리기]' |
| 아니오 · Esc · 바깥(스크림) 누르기 · 아래로 쓸어내리기 | 모두 '아니오' = 리마인드 유지, 토스트 '리마인드 유지'. 아무것도 고르지 않으면 누락 0 쪽으로(D23 · D48) |
| 오늘 다시 보지 않음 | 체크 후 [예]면 다음 R-아침 알림 시각까지 답장 시 시트 없이 바로 완료(`reply_auto`), 아침 알림에서 되돌리기(D48) |
| 배치 | 모달. 휴대폰은 화면 아래에 붙은 전체 폭 + 손잡이, 840px 이상은 아래에서 24px 띄운 최대 560px 시트(손잡이 없음). 진입 300ms · 퇴장 200ms |
| 포커스 | 열리면 [예]에 포커스(되돌리기가 있으므로). Tab은 시트 안에서만, 닫히면 원래 자리로 |
| Outlook 답장(나) | 시트가 아니라 알림 센터 '알림' 탭에 "Outlook 답장 · 완료로 처리할까요? [예] [아니오]" |

### 13-6. 알림 센터 · 리마인더 · 토스트

| 요소 | 규칙 |
|---|---|
| 🔔 숫자 | 지금 챙길 리마인더 수(처리된 업무의 리마인더는 빠짐). 일반 알림은 숫자에 넣지 않는다. 10 이상은 9+ |
| 알림 센터 | 🔔 아래 400px. 탭 **[리마인더 \| 알림]**, 리마인더가 기본 탭 |
| 리마인더 탭 | 줄: ⏰ + 업무 · 사유(기한 3시간 전 / 기한 지남 D+N / 나중에 시각 도래 / 아침 알림) · 발신자 · 메일 제목 + **[완료] [나중에 ▾] [메일 보기]**. 나중에 = 1시간 뒤 · 오늘 오후 4시 · 내일 아침(08:30) · 다음 주 월요일 09:00 · 직접 고르기. [메일 보기]는 메일 화면으로 |
| 알림 탭 | 오늘 · 이전 묶음, 안 읽은 점. 종류: Outlook 답장 · 완료로 처리할까요?(예/아니오) · 새 업무 N건 · 아침 알림(미처리 N건 · 답장으로 바로 완료 N건 + 되돌리기) · 휴대폰 알림 안내(iOS는 홈 화면 추가 후) |
| 리마인더 토스트 | 리마인더가 도착하면 오른쪽 아래에 흰 카드 토스트: "기한 3시간 전 · 업무 · 오늘 18:00 · 발신자" + [나중에] [완료]. **자동으로 사라지지 않는다**(닫아도 알림 센터에 남음) |
| 일반 토스트 | 검정 바탕. 정보 5초, 되돌리기가 있으면 8초, 마우스 · 포커스가 있으면 멈춤. 동시에 3개까지(넘으면 오래된 것부터 닫음). 오류만 `role="alert"`, 나머지는 `role="status"` |
| 운영체제 알림 · 웹 푸시 | 같은 문구를 쓴다. 휴대폰 웹 푸시는 홈 화면에 설치한 PWA만(R4), 안내는 알림 탭에서 사용자가 누를 때 |

### 13-7. 메일 화면 S1 v3.1

2절 3단 구조(Outlook 레퍼런스)를 유지하고, 업무 기능을 얹는다. 대시보드에서 업무 · 확인사항 · 리마인더를 누르면 여기로 온다. v3.2: 읽기 머리를 Outlook 받은 메일 보기 순서로 맞추고(UX-D14), 플래그 칩(UX-D13) · [메일 요약](UX-D15) · 본문 형광펜(UX-D16)을 더한다.
