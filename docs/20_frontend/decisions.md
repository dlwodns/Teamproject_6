## FE-D8 · 프론트 테스트는 `node --test`로 돌린다 (2026-11-05)

- 상태: 제안(FE-1 구현 선택) · 제안: 임동하 · 결정: [미정] · 리뷰: [미정] · 공동: — · 근거: infra/plan.md 3-3 · INF-6
- 결정: `npm test` = `node --test "src/**/*.test.ts"`. Node 22.18 이상의 타입 제거 기능으로 TS 테스트를 별도 라이브러리 없이 돌린다(`tsconfig`의 `erasableSyntaxOnly` · `allowImportingTsExtensions`).
- 근거: vitest 4.1.10 ~ 4.1.12를 npm 10.9.8로 설치하면 `Cannot read properties of null (reading 'edgesOut')`로 설치가 멈췄다(선택적 peer 의존성 해석 중). 4.0.18은 설치되지만 Vite 7을 따로 끌어온다.
- 대안: Vitest(infra/plan.md 3-3 권장 `[제안]`) — 위 오류로 보류. npm · vitest가 고쳐지면 다시 검토한다.
- 위험 · 남은 일: infra 권장 도구와 다르다. 컴포넌트 · 브라우저 테스트가 필요해지면 도구를 다시 정한다.

## FE-D9 · Node 22.18 이상을 요구하고 설치 때 엔진 조건을 강제한다 (2026-11-05)

- 상태: 제안(FE-1 구현 선택) · 제안: 임동하 · 결정: [미정] · 리뷰: [미정] · 공동: — · 근거: INF-1(`.nvmrc` 22) · FE-D8
- 결정: `frontend/package.json` `engines.node` = `>=22.18.0`, `frontend/.npmrc` `engine-strict=true`(이 폴더의 `npm install` · `npm ci`에만 적용).
- 근거: `node --test`의 TS 타입 제거가 22.18부터 기본으로 켜진다. Vite 8은 `^20.19.0 || >=22.12.0`을 요구한다. 조건이 맞지 않으면 설치 단계에서 멈추게 해 원인을 바로 알 수 있게 한다.
- 대안: engines `>=22.12.0`(Vite 기준) — 22.12~22.17에서 테스트가 돌지 않는다.
- 위험 · 남은 일: `.nvmrc`는 `22`라 22.18 미만을 막지 않는다. CI(`actions/setup-node`, `node-version-file: .nvmrc`)가 받는 22.x가 22.18 이상인지는 PR CI에서 확인한다.

## FE-D10 · FE-1 대시보드 임시 집계 기준 (2026-11-05)

- 상태: 제안(FE-1 구현 선택 · BE-3에서 맞출 기준) · 제안: 임동하 · 결정: [미정] · 리뷰: [미정] · 공동: — · 근거: 구조도 5절 · D20 · D39 · D40 · `backend/scripts/demo_expected.py`
- 결정(완료율): 칸 · 미처리 수는 `pending`만. 완료율 = 완료 ÷ (미처리 + 나중에 + 완료), 제외는 분모에서 뺀다. 업무가 없으면 완료율을 비운다.
- 결정(공지 정책): 업무 성격 칸은 업무가 나온 메일의 `category`로 정한다. 공지 분류 메일에 업무가 있으면 '기타'에 넣는다(`NOTICE_TASK_POLICY = 'other'`). 업무 레코드와 전체 업무 수에서는 어느 경우에도 빼지 않는다. 분류 전(null) 메일의 업무도 '기타'.
- 결정(기한 판정): 기한 지남 `due_at < 기준 시각`, 오늘 마감(기한 남음) 같은 KST 날짜이고 `due_at >= 기준 시각`, 내일 = 다음 KST 날짜. 기한 유무는 `due_at`으로만 판단한다(`due_source` 안 씀). 브라우저 시간대와 무관하게 KST로 계산한다.
- 근거: 구조도 5절은 상태별 포함 여부만 있고 완료율 분모가 없다. D40은 공지 칸을 빼고 공지 메일은 업무를 만들지 않는다고만 해, 그래도 업무가 생긴 경우의 칸은 문서에 없다 → 누락 방지(D13)를 우선했다. 기한 판정은 `demo_expected.py`의 시연 기대값 정의와 같다.
- 대안: 공지 업무를 업무 성격 칸에서 빼기(`'exclude'`, 상수 한 곳만 바꾸면 된다). 완료율 분모에 제외 포함 · 나중에 제외.
- 위험 · 남은 일: 더미 v1에서 공지 메일 업무는 0개라 지금 화면 숫자에는 영향이 없다. BE-3가 집계를 서버에서 할지 정하면 같은 기준으로 맞춘다.
