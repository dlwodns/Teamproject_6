## 1. 결정

### UX-D1 · 대시보드는 '업무'와 '확인사항'을 나눠 보여 준다 (2026-11-07)

- 상태: 채택 · 제안: 문규남 · 결정: 문규남(UX/UI, 11-07) · 리뷰: 이재운(기획 확인, PR #27 11-07) · 공동: — · 근거: D40 · AI-D10(`lane`) · `ai/app/pipeline/checks.py`
- 결정: 업무(lane=할 일)는 2열 칸에, 업무가 아닌 메일은 1열 '확인사항' 카드에 둔다. 카드 탭은 `확인`(완료 보고 · 결과 회신 · 해당 여부 확인 · 시스템 알림 · 읽고 확인)과 `참고`(일반 공지 · 공유 · 뉴스)이고 기본은 확인 탭이다. 기본 3건, 나머지는 더보기로 오른쪽 사이드바(UX-D12). 이름은 처음 '알아둘 정보'였다가 UX-D11에서 '확인사항'으로 바꿨다.
- 근거: 확인 · 참고 메일은 업무로 세면 정밀도가 떨어지고(AI-T5), 버리면 정보를 잃는다. 사용자는 공지처럼 알아야 할 정보도 대시보드에서 보길 원했다.
- 바뀐 것: D40 "공지 · 참조는 메일 화면에서 분류로만 보인다" → 대시보드 '확인사항'에도 보인다. 업무를 만들지 않는다는 결정은 그대로다.

### UX-D2 · 1열은 받은 날 기준 업무 수(건수만)다 (2026-11-07)

- 상태: 채택 · 제안: 문규남 · 결정: 문규남(11-07) · 리뷰: 이재운(기획 확인, PR #27 11-07) · 근거: D20-1 · D20-4
- 결정: 1열 맨 위 카드는 **메일을 받은 날** 기준으로 들어온 업무의 전체 · 처리 · 미처리 건수만 보인다. 기간은 오늘 · 이번 주 · 날짜(하루 고르기). 미처리 = 미처리 + 나중에, 제외는 세지 않는다. 그 아래에 '응답 대기'(F10)와 '확인사항'(UX-D1)을 둔다 `[제안]`.
- 바뀐 것: D20-1 요약 줄 · 원형 진행률, D20-4 1열 우선 확인(기한 · 상급자 · 즐겨찾기) 칸을 없앤다. 기한 관련은 2열 긴급(UX-D3)으로, 상급자 · 즐겨찾기는 줄 표시와 정렬(D9 가중치)로 옮긴다.
- 대안: 기한 날 기준 — 기한 없는 업무가 빠져서 택하지 않았다.

### UX-D3 · 2열은 긴급 + 업무 유형 4칸이다 (2026-11-07)

- 상태: 채택 · 제안: 문규남 · 결정: 문규남(11-07) · 리뷰: 이재운(기획 확인, PR #27 11-07) · 근거: D39 · D40 · AI-D11(ASAP 문구)
- 결정: 2열 맨 위 '긴급' 칸 = 미처리 중 기한 지남 · ASAP(즉시) · 오늘 마감. 아래 유형 칸 = 회신 · 요청 · 검토 · 기타(공지는 업무를 만들지 않아 칸 없음). 긴급 업무도 유형 칸에 같이 보인다(중복 허용).
- 결정(D40 공지 속 지목 요청, #27 리뷰): 업무 칸은 업무가 나온 메일의 분류(`category`)로 정한다. 공지 속 나를 지목한 요청은 ai가 분류를 공지가 아니라 그 요청의 분류(대부분 '요청', 회신 · 검토 요청이면 그 칸)로 낸다(`ai/app/pipeline/classify.py` `_category`, D40) → 따로 칸을 두지 않아도 해당 유형 칸에 들어간다. 분류가 '공지'인데 업무가 붙은 예외(분류 전 · 수동 분류 등)는 '기타' 칸에 둔다 — FE-D10 임시 정책(`NOTICE_TASK_POLICY = 'other'`)과 같은 방향이고, 업무 수에서는 빼지 않는다(D13).
- 바뀐 것: D20-4 2열 성격 칸(요청 · 보고 · 문의 · 공지 · 기타)과 칸 끌어서 순서 바꾸기(P0)를 없앤다. wireframe 12-5 #1('문의')은 D39로, #3(1열 칸 사이 중복)은 1열이 건수 카드가 되면서 해소됐다.

### UX-D4 · 색은 60 · 35 · 5(무채색 · 보조 4색 · LG 빨강), 서체는 Pretendard + Outfit (2026-11-07)

- 상태: 채택(방향) · 세부 값 `[제안]` · 제안: 문규남(LG CNS 브랜드 로고와 함께 쓰는 색) · 결정: 문규남(11-07) · 리뷰: 이재운(기획 확인, PR #27 11-07) · 근거: LG CNS 사이트 CSS · 로고 SVG(`research_ux_20261107.md` 1절)
- 결정: 60% 무채색 면(#FFFFFF · #F7F8F9), 35% 보조 4색(#121212 · LG GRAY #6B6B6B · #E5E5E5 · #F0F1F3), 5% 포인트 LG Heritage Red #A50034(주 버튼 · 에이전트 버튼 · 선택 표시선 · 로고만). 상태색은 따로(위험 #B20C00 등)이고 옅은 바탕 + ⚠ + 글자로만 쓴다. 국문 제목 · 본문 · 영문 본문 Pretendard, 영문 표시 · 숫자 Outfit. 상세는 `design_system.md`.
- 바뀐 것: D21(LG RED를 '요청' 태그 · 강조 아이콘에도) → 포인트 사용처를 줄였다. FE-D7(오렌지 #FF6000 가이드, FE-1 브랜치) → 이 결정으로 대체, `frontend/src/styles/tokens.css` 교체 필요(FE-2).
- 위험: 로고 사용 허락 전에는 '로고 자리'를 둔다. LG 전용 서체(LG EI)는 외부 사용 조건 미확인이라 쓰지 않는다.

### UX-D5 · 답장은 만든다 — 하고 싶은 말만 쓰면 템플릿에 맞춰 보여 준다 (2026-11-07)

- 상태: 채택 · 제안: 문규남 · 결정: 문규남(11-07) · 리뷰: 이재운(기획 확인, PR #27 11-07) · 근거: D48 · wireframe 0절
- 결정: 메일 화면에서 답장을 쓴다(UX-D12로 대시보드 메일 패널은 없앰). 사용자는 보낼 내용만 쓰고, 고른 템플릿(기본 회신 · 자료 송부 · 일정 회신 · 확인했습니다)의 인사 · 맺음 · 서명 사이에 넣어 미리보기로 보여 준다. 보내기는 사용자가 누를 때만. 엑사원으로 다듬기(`/draft`)는 선택.
- 결정: 완료 확인 문구는 **"완료로 처리할까요?" · 예 / 아니오 · 체크박스 "오늘 다시 보지 않음"**.
- 바뀐 것: wireframe 0절 '만들지 않는 것'에서 답장을 뺐다. D48 문구 "완료할까요? · 오늘 하루 보지 않기"를 이 문구로 바꾼다(동작은 D48 그대로). 템플릿 자리표시자에 `{내용}` · `{발신자명}`을 더한다(BE 확인).

### UX-D6 · 답장 후 완료 확인은 아래 시트로 띄운다 (2026-11-07)

- 상태: 채택 · 제안: 문규남 · 결정: 문규남(11-07) · 리뷰: 이재운(기획 확인, PR #27 11-07) · 근거: D23 · D48 · M3 · NN/g bottom sheet · WAI-ARIA dialog
- 결정: 모달 아래 시트. 휴대폰은 전체 폭 + 손잡이, 840px 이상은 최대 560px로 아래에서 24px 띄운다. 아니오 · Esc · 바깥 누르기 · 쓸어내리기는 모두 '아니오'(리마인드 유지). 열리면 [예]에 포커스(되돌리기가 있으므로).

### UX-D7 · 알림 센터에 리마인더 탭을 따로 둔다 (2026-11-07)

- 상태: 채택 · 제안: 문규남 · 결정: 문규남(11-07) · 리뷰: 이재운(기획 확인, PR #27 11-07) · 근거: 리마인더 R-아침 · R-기한 · R-나중에 · Outlook 리마인더 창 · Slack Later
- 결정: 🔔 알림 센터를 [리마인더 | 알림] 탭으로 나누고 리마인더를 기본으로 연다. 리마인더 줄마다 [완료] [나중에 ▾] [메일 보기]. 🔔 숫자는 리마인더만 센다. 리마인더 토스트는 자동으로 사라지지 않는다.

### UX-D8 · 에이전트는 접히는 단계 표시 + 대화 안 확인 카드 + 결과 카드로 보여 준다 (2026-11-07)

- 상태: 채택 · 제안: 문규남(스텝 인디케이터) · 결정: 문규남(11-07) · 리뷰: 이재운(기획 확인, PR #27 11-07) · 근거: D37 · Vercel AI Elements · Fluent Wait UX · NN/g · Linear · Notion(`research_ux_20261107.md` 2절)
- 결정: 단계 명령 이해 → 대상 찾기 → (확인) → 실행. 진행 중엔 한 줄("…하는 중 · n/전체 · 경과 초" + [중지]), 끝나면 "N단계 완료 · M초"로 접고, 실패하면 펼친 채 멈춘다. 확인은 모달이 아니라 대화 안 카드(동사 버튼, 대상 빼기 가능). 결과 카드는 과거형 + [실행 취소] + 해석 근거(접힘). 남은 시간은 추정하지 않고 경과 시간만 보인다.

### UX-D9 · 버튼 모핑은 네 곳에만 쓴다 (2026-11-07)

- 상태: 채택 · 제안: 문규남 · 결정: 문규남(11-07) · 리뷰: 이재운(기획 확인, PR #27 11-07) · 근거: Carbon productive motion · M3 motion 토큰 · Primer loading
- 결정: 업무 체크 → 줄 빠짐, 보내기 → 보내는 중 → 보냄 ✓, ✦ 버튼 → 에이전트 패널(컨테이너 변형), 아래 시트 등장. 필터 · 탭 · 숫자 갱신에는 쓰지 않는다. 동작 줄이기 설정이면 모두 끈다. 값은 `design_system.md` 4절.

### UX-D10 · 기한 라벨은 검정 · 파랑 · 초록이고 짧게 쓴다 (2026-11-07)

- 상태: 채택 · 제안: 문규남 · 결정: 문규남(11-07) · 리뷰: 이재운(기획 확인, PR #27 11-07) · 근거: UX-D4(빨강은 포인트 전용)
- 결정: 기한 지남 · ASAP = 검정 라벨(`D+2` · `ASAP`), 오늘 마감 = 파랑(`오늘 18:00`), 기한 남음 = 초록(`내일 12:00` · `11/10(화)`), 기한 없음 = 회색. ⚠ · '기한 지남' 같은 말은 라벨에 붙이지 않는다. 값은 `design_system.md` 1절.
- 근거: 빨강은 포인트(LG Heritage Red)와 대비 1.11:1이라 위험 표시에 쓰면 섞인다. 가장 급한 것을 가장 진한 색으로 두면 색이 섞이지 않고 순서가 바로 읽힌다.

### UX-D11 · 문구는 명사로 짧게, 덜어낼 수 있는 줄은 없앤다 · 메일함은 Ctrl+B로 열고 닫는다 (2026-11-07)

- 상태: 채택 · 제안: 문규남 · 결정: 문규남(11-07) · 리뷰: 이재운(기획 확인, PR #27 11-07) · 근거: D20-3 · UX-D5
- 결정: 대시보드 화면 제목 · 설명 줄과 기한 지남 경고 줄(A1, '긴급 칸에서 보기')을 없앤다. 긴급 칸 설명('기한 지남 · ASAP · 오늘 마감')도 없앤다. 이름은 '업무 있는 메일' → '업무', '알아둘 정보' → '확인사항', '답장 기다리는 메일' → '응답 대기', '처리함 · 남음' → '처리 · 미처리'. 빈 상태는 '없음'. 완료 확인 시트는 제목 · 업무 목록 · 체크박스 · 버튼만.
- 결정: 메일 화면 왼쪽 메일함 = 받은편지함 · 업무 · 확인사항 / 빠른 보기(즐겨찾기 · 상급자 · 기한 지남 · 응답 대기) / 분류 / 계정. 목록 위 [▥] 버튼과 Ctrl+B(⌘B)로 열고 닫는다.
- 바뀐 것: D20-3(기한 지남 경고 줄) → 없앰. 긴급 칸과 검정 라벨이 대신한다.

### UX-D12 · 더보기는 오른쪽 사이드바, 업무를 누르면 그 메일로 간다 (2026-11-07)

- 상태: 채택 · 제안: 문규남 · 결정: 문규남(11-07) · 리뷰: 이재운(기획 확인, PR #27 11-07) · 근거: UX-D1 · UX-D3
- 결정: 대시보드의 모든 더보기(긴급 · 유형 칸 · 응답 대기 · 확인사항)는 칸 안에서 펼치지 않고 오른쪽 480px 사이드바에 전부 보여 준다. 업무 줄 · 확인사항 줄 · 리마인더 [메일 보기]를 누르면 메일 화면으로 넘어가 그 메일을 고른다.
- 결정: 메일 화면 맨 위에 [← 대시보드] 버튼을 따로 두고, Alt+← / Alt+→로 이전 · 다음 화면을 오간다(입력칸 안에서는 제외). 실제 앱은 라우터 history로 만들어 브라우저 뒤로 가기와 같게 한다.
- 바뀐 것: D20-6(업무 줄 → 오른쪽 원본 메일 패널)과 wireframe 12절 `M` 패널 → 없앰. 답장 · 상태 버튼은 메일 화면에서 쓴다.

## FE-D10 · FE-1 대시보드 임시 집계 기준 (2026-11-05)

- 상태: 제안(FE-1 구현 선택 · BE-3에서 맞출 기준) · 제안: 임동하 · 결정: [미정] · 리뷰: [미정] · 공동: — · 근거: 구조도 5절 · D20 · D39 · D40 · `backend/scripts/demo_expected.py`
- 결정(완료율): 칸 · 미처리 수는 `pending`만. 완료율 = 완료 ÷ (미처리 + 나중에 + 완료), 제외는 분모에서 뺀다. 업무가 없으면 완료율을 비운다.
- 결정(공지 정책): 업무 성격 칸은 업무가 나온 메일의 `category`로 정한다. 공지 분류 메일에 업무가 있으면 '기타'에 넣는다(`NOTICE_TASK_POLICY = 'other'`). 업무 레코드와 전체 업무 수에서는 어느 경우에도 빼지 않는다. 분류 전(null) 메일의 업무도 '기타'.
- 결정(기한 판정): 기한 지남 `due_at < 기준 시각`, 오늘 마감(기한 남음) 같은 KST 날짜이고 `due_at >= 기준 시각`, 내일 = 다음 KST 날짜. 기한 유무는 `due_at`으로만 판단한다(`due_source` 안 씀). 브라우저 시간대와 무관하게 KST로 계산한다.
- 근거: 구조도 5절은 상태별 포함 여부만 있고 완료율 분모가 없다. D40은 공지 칸을 빼고 공지 메일은 업무를 만들지 않는다고만 해, 그래도 업무가 생긴 경우의 칸은 문서에 없다 → 누락 방지(D13)를 우선했다. 기한 판정은 `demo_expected.py`의 시연 기대값 정의와 같다.
