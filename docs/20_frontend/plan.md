# 프론트엔드 구현계획

> 상태: 결정 · 작성: 문규남 · 결정: 문규남(11-12) · 리뷰: [미정] · 갱신: 2026-11-12(v3.3 — 화면 기반 · 단계별 일정으로 다시 씀, 이전 판은 git 기록)
> 일정 기준: 11/18 첫 배포 · 11/20 발표자료 초안 · 11/27 코드 마감 · 11/28 IR Day

## 1. 목표

와이어프레임 13절(v3.1 · v3.2)의 대시보드 · 메일 · 에이전트 패널 · 알림 센터를 11/27까지 실제 서버에 붙여 시연 장면 ①~⑧이 화면에서 끝까지 돌게 한다. 화면 설계는 끝났으므로(UX-D1 ~ UX-D16) 남은 일은 구현이다.

지금 main에는 골격(FE-1)과 토큰(FE-2)만 있고, 대시보드는 v2 구조를 모의 데이터로 보여 주는 단계다. 가장 시간이 많이 드는 부분은 팝업 · 시트 · 토스트처럼 접근성 동작이 까다로운 부품을 손으로 만드는 일이었다. 그래서 순서를 바꿔 **공통 기반(고정 토큰 · 헤드리스 부품 · 상단 바 · 주소 · 데이터 층)을 먼저 하루에 끝내고**, 그 위에서 화면 네 갈래를 동시에 만든다.

## 5. 다른 파트와의 접점

| 방향 | 상대 파트 | 내용 | 필요한 날 |
|---|---|---|---|
| 받는 것 | 백엔드 | 대시보드 원자료(BE-3, PR #47) | 11/17 |
| 받는 것 | 백엔드 | 메일 한 통(본문 · 받는 사람 · 언어 · 근거 문장) · 응답 대기(BE-13) · 리마인더(BE-12) · 명령 창구(BE-11 #50, T01 · T06 · T07 결과 종류는 FE 제안) | 11/18 ~ 11/19 |
| 받는 것 | 백엔드 · AI | 메일의 확인 · 참고 구분(lane), 업무 유형 · 원문 기한(`due_raw`) — 대시보드 응답에 칸 추가 | 11/17 |
| 받는 것 | AI | 명령 해석 응답 형식(`/agent/plan`) — 모의 응답을 이 형식으로 만든다 | 있음 |
| 주는 것 | AI | 음성 인식 결과 글자 → 명령 입력 | 11/18 |

없는 API는 화면을 막지 않는다. 모의 모드로 먼저 만들고, 실제 서버 모드에서는 그 칸을 숨긴다(`components.md` 1절 6번).

## 6. 완료 기준 (입력 → 기대 결과)

- wireframe 13-9 확인 표 V-1 ~ V-27을 모의 데이터 v2로 모두 통과한다.
- 실제 서버 모드에서 시드를 적재하고 업무 하나를 완료하면, 다시 불러도 미처리가 1 줄어 있다.
- `components.md` 6절 키보드 점검표 1~6을 통과한다.
- `npm test` · `npm run build`가 통과하고 토큰 고정 테스트가 그대로다.
