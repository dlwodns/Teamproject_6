## 0. 고정 규칙 — 토큰은 바꾸지 않는다

이 문서에 적힌 색 · 글꼴 · 글자 크기 · 간격 · 모서리 · 그림자 · 움직임 · 겹침 · 배치 값은 v3.3으로 **고정**한다. 화면을 만드는 동안 값이 흔들리면 같은 화면이 사람마다 다르게 나오고, 접근성 대비 검사도 매번 다시 해야 하기 때문이다. 새 화면에 맞는 값이 없으면 토큰을 새로 만들지 말고 가장 가까운 토큰을 쓴다.

- **어디에 있나.** 실제 값은 `frontend/src/styles/tokens.css` 한 곳에 있다. 같은 값을 디자인 토큰 표준 형식(DTCG 2025.10)으로 옮긴 고정 기록이 `cne.tokens.json`이고, 피그마가 받을 수 있는 값만 추린 것이 `cne.figma.tokens.json`이다. 두 JSON은 스크립트가 만들며 손으로 고치지 않는다.
- **어떻게 지키나.** 프론트 테스트가 세 가지를 확인한다. tokens.css와 두 JSON이 같은지, JSON의 해시가 아래 '고정 해시'와 같은지, 화면 CSS에 색 HEX를 직접 쓰지 않았는지다. 하나라도 어긋나면 테스트가 실패한다.
- **바꿔야 할 때.** decisions.md에 UX-D 항목을 새로 올려 결정한 뒤, 같은 커밋에서 tokens.css를 고치고 `npm run tokens:export`로 JSON을 다시 만들고 아래 고정 해시를 새 값으로 바꾼다. 리뷰어는 해시 줄이 바뀐 PR을 보면 토큰이 바뀌었다는 것을 바로 안다.
- **라이브러리를 써도 겉모습은 토큰으로만.** 화면 부품을 헤드리스 라이브러리(Base UI, FE-D14) 위에 만들더라도 라이브러리 기본 테마는 불러오지 않는다.
- **임시 토큰.** FE-1 왼쪽 메뉴용 폭 두 개(`--sidebar-expanded` · `--sidebar-collapsed`)는 고정 대상이 아니다. 상단 바 메뉴(와이어프레임 13절 `T0`)로 옮기면 지운다.

고정 해시(cne.tokens.json SHA-256 앞 16자리): `c1afc9cba4c2e27b` · 토큰 84개 · 2026-11-12

**화면 폭 기준.** 미디어 쿼리에는 아래 다섯 값만 쓴다. 시안에 있던 600 · 700 · 860px 같은 중간값은 가장 가까운 기준으로 맞춘다.

| 폭 | 바뀌는 것 |
|---|---|
| 480px 이하 | 상단 바 사용자 사진을 숨기고 메뉴 글자를 줄인다 |
| 720px 이하 | 에이전트 패널 · 더보기 사이드바가 화면 전체 폭이 된다. 유형 칸이 한 열이 된다 |
| 840px 이상 | 아래 시트가 바닥에서 24px 떠 있는 최대 560px 카드가 된다(손잡이 없음) |
| 1024px 미만 | 대시보드 2열이 한 열로 쌓이고, 메일 3단이 위아래로 쌓인다 |
| 1280px 이상 | 패널을 열면 본문이 옆으로 밀려난다(그보다 좁으면 본문 위에 겹친다) |

## 1. 색 — 60 · 35 · 5

LG CNS 사이트도 무채색이 압도적이고(토큰 참조 수: 구분선 59 · 본문 글자 55 · 보조 글자 49 … 브랜드 빨강 11) 빨강은 포인트로만 쓴다. 그래서 **60%는 무채색 면, 5%가 LG 빨강**이다. 빨강을 넓게 깔면 촘촘한 업무 목록에서 눈이 피로하고 '기한 지남(위험)'과 구분되지 않는다.

**포인트 규칙**
- 포인트 빨강은 "채운 버튼"과 "선택 표시선"에만 쓴다. 글자 · 배지 · 아이콘 · 차트에 쓰지 않는다.
- 선택은 색만으로 나타내지 않는다: 메뉴는 굵은 글씨 + 밑줄, 분할 버튼은 흰 바탕 + 그림자, 메일함은 굵은 글씨 + 왼쪽 선.
- 체크 상자 · 진행 막대 · 단계 점은 빨강이 아니라 `--c-ink` · 완료색이다.
- 주 버튼 · ✦ 버튼의 마우스 올림은 따로 색을 두지 않고 `filter: brightness(0.9)`, 누름은 `--c-point-press`(FE-2 #33).

- 검정 라벨은 긴급 칸 제목 앞 점과 같은 색이라 "긴급 = 검정"으로 한 번에 읽힌다.

### 형광펜 — 업무 근거 문장 (UX-D16)

| 이름 · 토큰 | HEX | 어디에 | 대비 |
|---|---|---|---|
| `--c-mark` | #FFEB8A (결정 11-07) | 본문 속 업무 근거 문장 바탕(`<mark>`) | `--c-ink` 글자 15.61:1 · `--c-sub` 6.12:1 · 흰 바탕과 1.20:1 |
| `--c-mark-line` | #8E6A00 (결정 11-07) | 형광펜 문장 밑줄 2px | 흰 바탕 4.99:1 · `--c-mark` 위 4.16:1 |
| `--c-mark-strong` | #FFD84D (v3.3) | 업무 줄을 눌러 근거 문장으로 옮겨 갔을 때 잠깐 진해지는 바탕 | `--c-ink` 글자 13.54:1 |

- 형광펜 바탕은 흰 면과 1.20:1이라 **색만으로는 보이지 않는다** → 밑줄(`--c-mark-line` 2px, `text-underline-offset: 3px`)과 숨은 글자 '업무 근거'를 함께 둔다(WCAG 1.4.1). 링크와 헷갈리지 않게 글자색은 그대로 `--c-ink`이고, 밑줄은 바탕과 같은 노랑 계열 2px이다.
- 노랑 계열은 사이트 팔레트 yellow400 #BE5C01(흰 바탕 4.45:1)에서 밝힌 파생값이다. 포인트 빨강 · 정보 파랑과 겹치지 않는 유일한 색 계열이라 '본문 속 표시' 한 곳에만 쓴다.
- 업무 줄을 눌러 그 문장으로 옮겨 갈 때는 문장에 포커스 링(`--c-ink` 2px)을 0.8초 보인 뒤 형광펜만 남긴다(동작 줄이기 설정이면 링만 즉시).

- 칩 모양: 높이 20px · 모서리 `--r-chip`(4px) · 글자 12px 600 · 좌우 6px. 테두리 없음(바탕과 흰 면 대비가 낮아도 글자가 뜻을 말한다).

- 한 줄 순서: 상급자 → 즐겨찾기 → 거래처. 한 사람에 여러 개면 모두 붙인다(최대 3개).
- 거래처 칩 색(11-07 문규남): 다른 칩과 같은 회색으로 시작한다. 정보 파랑(#DDF3FB · #003374, 10.6:1)은 대안으로 남긴다. 화면에서 써 보고 구분이 약하면 UX-D 항목으로 결정한 뒤 바꾼다(0절 고정 규칙).

## 2. 서체

| 역할 | 서체 | 굵기 · 크기 | 근거 |
|---|---|---|---|
| 국문 제목 | **Pretendard** | 700 · 20 / 16 / 14px | LG CNS 사이트 `--typo-pc-family-head` |

| 영문 본문 | **Pretendard**(Inter 기반 라틴 글자 포함) | 국문과 같음 | 한 문장 안 한영 섞임에서 글자 높이가 맞는다 |
| 영문 표시 · 숫자 | **Outfit** 600 | 브랜드 'CNE' · 큰 숫자(업무 수 40px) · 시각 · 경과일 | LG CNS 사이트 메인 배너 `--typo-main-family` |

- 대체 순서: `"Pretendard Variable", Pretendard, -apple-system, BlinkMacSystemFont, "Apple SD Gothic Neo", "Malgun Gothic", "Noto Sans KR", sans-serif`
- 라이선스: Pretendard · Outfit 모두 SIL OFL 1.1 — 빌드에 넣어 배포할 수 있다(FE-1의 `public/licenses/` 고지 방식 유지). Outfit은 라틴 글자만 있어 한글에 쓰지 않는다.
- LG 전용 서체(LG EI Headline · LG EI Text, 예전 LG스마트체)는 "LG전자 전용 서체"이고 외부 사용 조건을 확인하지 못했다 `[미확인]` → 쓰지 않는다.
- 숫자가 세로로 줄 서는 곳(건수 · 시각)은 `font-variant-numeric: tabular-nums`.
- 크기 단계: 12 · 13 · 14 · 16 · 20 · 28 · 40px. 줄 간격 본문 1.5, 메일 본문 1.7.

**v3.3 고정 토큰.** 아래 값 말고 다른 크기 · 굵기를 쓰지 않는다. FE-1 화면에 남은 11px · 18px은 기반 작업 때 12px · 16px(또는 20px)로 맞춘다.

| `--fs-16` | 16px | 카드 제목 |
| `--fs-20` | 20px | 패널 · 시트 제목 |
| `--fs-28` · `--fs-40` | 28 · 40px | 큰 숫자(Outfit) — 업무 수 카드 |
| `--fw-regular` · `--fw-medium` · `--fw-semibold` · `--fw-bold` | 400 · 500 · 600 · 700 | 본문 · 강조 · 버튼과 칩 · 제목 |
| `--lh-body` · `--lh-mail` | 1.5 · 1.7 | 화면 글자 전체 · 메일 본문 |

- 줄 간격 1.5 이상은 한국 정부 디자인 시스템(KRDS)의 '모든 글자 스타일 줄 간격 150% 이상' 규칙과 같다. 12px은 KRDS 본문 최소(16px)보다 작으므로 문장이 아닌 짧은 보조 정보에만 쓴다.
- 날짜는 화면 문구 규칙(5절)대로 `11/6(금)` · `오늘 18:00`처럼 쓴다. 숫자만으로 연월일을 쓸 일이 있으면 `2026. 11. 12.` 형식(국립국어원 문장 부호 규정, 브라우저 한국어 날짜 기본 형식과 같음)을 쓴다.

## 4. 움직임 · 버튼 모핑

| 토큰 | 값 | 쓰는 곳 |
|---|---|---|
| `--d-fast` | 100ms | 누름 · hover 바탕 |
| `--d-short` | 150ms | 체크 · 내용 바꿈(버튼 안 글자 ↔ 스피너) · 팝오버 |
| `--d-move` | 250ms | 줄 빠짐 · 토스트 등장 |
| `--d-panel` | 300ms | 패널 · 시트 등장 |
| `--d-exit` (v3.3) | 200ms | 패널 · 시트 퇴장 · 줄 높이 접힘 |
| `--d-morph` (v3.3) | 350ms | ✦ 버튼이 에이전트 패널로 자라는 변형 |
| `--e-std` | cubic-bezier(.2,0,0,1) | 기본(M3 emphasized) |
| `--e-in` | cubic-bezier(.05,.7,.1,1) | 들어올 때(감속) |
| `--e-out` | cubic-bezier(.3,0,.8,.15) | 나갈 때(가속) |

**모핑을 쓰는 곳과 안 쓰는 곳** — 업무 화면이라 '간결하고 눈에 덜 띄는' 쪽(Carbon productive)이 기본이다.

| 상호작용 | 모핑 | 방식 |
|---|---|---|
| 업무 ☐ → ✓ → 줄 빠짐 | O | 체크 150ms → 오른쪽으로 빠지며 흐려짐 250ms → 높이 접힘 200ms(`grid-template-rows: 1fr → 0fr`) |
| [보내기] → 보내는 중 → 보냄 ✓ | O | 같은 자리에서 내용만 바꾼다. 글자는 `visibility`로 숨겨 **버튼 폭을 유지**, 스피너는 위에 겹침. ✓는 0.7초 뒤 시트로 넘어감 |
| ✦ 에이전트 버튼 → 패널 | O | 컨테이너 변형 350ms(`document.startViewTransition`, 미지원이면 미끄러짐) |
| 아래 시트 | O | `<dialog>` + `@starting-style`로 아래에서 올라옴 |
| 필터 · 기간 바꾸기 · 탭 | X | 즉시 바꾼다(숫자가 튀지 않게) |

- 1초 안에 끝나는 일에는 스피너를 띄우지 않는다(300~400ms 지연 뒤 표시).
- 로딩 중 버튼은 `disabled`가 아니라 `aria-disabled="true"`(포커스 유지), 상태 문구는 숨긴 `aria-live="polite"` 영역에 "보내는 중" · "보냈어요".
- `prefers-reduced-motion: reduce`면 이동 · 변형 · 깜빡임을 끄고 상태 바뀜만 즉시 보인다.
- `interpolate-size`(height: auto 애니메이션)는 Chrome 계열만 지원 → 쓰지 않는다.

## 5. 문구

| 원칙 | 예 |
|---|---|
| 진행 중은 진행형, 끝나면 과거형 | "대상 업무를 찾는 중…" → "3건을 완료로 바꿨어요" |
| 버튼은 일어날 일을 동사로 | [3건 완료 처리] [메일 보내기] [다시 시도]. 확인 시트만 사용자가 정한 "예 / 아니오" |
| 필요 없는 말은 덜어낸다 | 화면 제목 · 설명 줄 · 경고 줄을 두지 않는다. 빈 상태는 "없음", 오류는 "불러오지 못함 [다시 시도]", 시트에는 제목 · 체크박스 · 버튼만 |
| 결과는 한 줄로 | "3건을 완료로 바꿨어요" · "리마인드 유지" · "중지했어요. 바뀐 것은 없어요" |
| 사용자 말로, 명사로 짧게 | lane=할 일 → '업무', lane=확인 · 참고 → '확인사항', excluded → '제외', snoozed → '나중에', 답장 대기 → '응답 대기' |
| 존댓말은 '~해요' 체로 통일 | 버튼 · 메뉴는 명사형('완료', '나중에', '메일 화면에서 열기') |
| 날짜 | 11/6(금) · 오늘 18:00 · 내일 12:00 · D+2. 모든 시각 KST |

화면 문구는 모두 한국어다. 고유명사(CNE · Catch & End · ASAP)만 영문.

## 6. 접근성 체크

- 글자 4.5:1, 상태 표시 · 포커스 링 · 입력칸 테두리 3:1 이상(FE-1 `contrast.test.ts`로 토큰 값 검사 유지).
- 포커스 링: 2px `--c-ink` + 2px 띄움, 모든 버튼 · 줄 · 칩.
- 키보드만으로: Tab으로 업무 줄 체크 · 메일 이동 · 답장 · 보내기 · 시트 예/아니오까지. 메일 화면에서 Ctrl+B(⌘B)로 메일함 열고 닫기(`aria-keyshortcuts`). Esc는 메뉴 → 알림 센터 → 패널 순으로 하나씩 닫는다. 시트 위에서 Esc는 '아니오'.
- 화면 읽기: 토스트 영역 `role="status"`, 에이전트 패널 `role="status"` 한 곳에 단계 문구만. 오류만 `role="alert"`.
- 색만으로 정보를 주지 않는다: 기한 라벨은 글자 자체가 상태를 말한다(D+2 · ASAP · 오늘 · 날짜), 선택은 굵기 · 선, 새 업무 점에는 `aria-label="새 업무"`.
